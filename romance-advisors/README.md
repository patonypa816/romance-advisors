# 恋爱军师团

运行在本机的互动情景剧游戏：观众投稿、投票，男主采用建议并发送消息，女生回应后结算亲密度。游戏采用单进程 Python 与 SQLite，可单独玩文字版，也可连接同级 `ai-live-avatar/studio/` 数字人和 `dyhub/` 抖音事件采集器。

## 当前玩法

一场直播可以玩多期，每期随机生成一对虚构成年角色与处境，一期包含多轮聊天。亲密度初始为 50，到 100 成功、到 0 失败；换期换人，不继承人物成长。

1. **征集**：评论逐条保存，同作者后发闲聊不覆盖先前建议。模型从真实投稿选出 0–4 项，每位作者最多占一个选项；短句和接梗也可成为建议。建议是否冒险或符合人设，与建议资格分开。没有适用项时男主自拟。
2. **投票**：发送当前编号，如 `1`、`投1`、`投 1`。每位作者以截止前最后有效票为准，重复投不加票，非法改票不清旧票。平票从最高票并列项抽一次；零票由男主从现有项中选择或自拟，不伪造票数。
3. **裁决**：最高票符合性格就采用；只有发生性格冲突时，才约 75% 仍采用、约 25% 改选其他观众项或自拟。票数、骰子与合法来源保存，刷新或失败重试不重抽。改选归实际作者，自拟不挂作者。
4. **聊天与结算**：每个正常回合产生一条男主消息和一条女生回复。女生只依据她可知的人设与正式聊天回应，不知道落选建议、隐藏骰子或男主私有思考。女生回复、分数和回合结果一次保存，技术失败不冒充剧情结果。

累计最强榜按加分次数÷有效采纳次数排序，狗头榜按减分次数÷有效采纳次数；零变化只计分母，技术失败不计成绩。终局另冻结本期奖项：最强按加分率，狗头按累计扣分；无人扣分时从本期有效建议作者随机。正式榜仅统计可信的同一次抖音直播中的真实建议，跨期、刷新和同场重启保留，下一次真实开播使用新榜；本地模拟独立统计。

**礼物不增加投票。** 礼物改变独立的造型值，聊天改变亲密度。造型值从 50 开始，范围 0–100，默认六档为鱼头 0、粗糙 1–19、疲惫 20–39、普通 40–59、精致 60–79、巨帅 80–100；门槛可配置。一钻组合的小心心 `463` 加分、抖音 `164` 减分，按可信事件单价×连击新增件数记账，同组重发不重复计分。真实接入步骤见教程。启用人物外观快照时，女生可在造型变化后给出 −2～+2 的印象修正；它不能单独触发终局，军师榜仍只按聊天分计算。

## 模块与原理

| 入口 | 职责 |
| --- | --- |
| `romance/game.py`、`storage.py` | 阶段窗口、建议来源、票数、一次裁决、SQLite 保存与榜单 |
| `romance/model.py` | 人物、建议理解与对白；程序校验返回结构，模型不能直接改票或数据库 |
| `romance/server.py`、`launcher.py` | 本机工作台、接口与启动管理 |
| `romance/program.py`、`performance.py`、`casual.py`、`avatar_client.py` | 自动推进、正式表演、普通互动与 Studio 连接，共用发送器 |
| `romance/auto_source.py`、`dyhub_intake.py`、`viewer_avatar.py` | 开播场次识别、房间事件去重与头像校验 |
| `romance/appearance*.py` | 造型配置、礼物账本、连击增量与免费试玩 |
| `static/renderer.js`、`scene-layout.js`、`obs-output.html` | 聊天、投票、榜单与 1080×1920 节目输出 |

窗口只控制建议与计票资格。生成中、关窗后收到的评论可以留作普通互动，但不能补进已经截止的游戏投票。正式表演与普通互动共享发送器；正式台词优先，未开口的过时内容撤销。数字人模式中，男主发消息动作的发送回执控制消息公开，随后生成女生回复；发送回执本身不能证明云端已经完整播放。

## 本地检查与边界

在本目录、安装依赖后执行：

```sh
PYTHONPATH=.:tests .venv/bin/python -m unittest discover -s tests
node --test tests/test_*.cjs
```

合成测试用于检查计票、来源、状态恢复、结算和前端行为；模拟评论、静态排版和免费造型试玩不是真实观众、云端换形或直播验收。创建文字剧情会请求模型；启动数字人会创建计费云会话。真实评论身份、礼物数量、RTC 音画、动作效果、OBS 输出和云端结束须在自己的授权环境分别核验。
