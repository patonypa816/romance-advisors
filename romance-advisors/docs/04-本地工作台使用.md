# 本地工作台使用

工作台支持纯文字游戏、数字人节目和本地模拟。首次安装、Studio 账号、音色与六档资产配置见[根目录说明](../../README.md)；真实房间与礼物见[采集教程](05-抖音评论与头像.md)。所有账号、房间、素材和外部文件路径均由操作者自行配置。

## 安装、启动与保存

需要 Python 3.11+。在 `romance-advisors/` 目录执行：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m romance.launcher
```

Mac 也可双击本目录的 `启动游戏工作台.command`；它打开本项目已有实例，或在 `127.0.0.1` 空闲端口启动。`停止游戏工作台.command` 只停止本项目实例。开发时可前台运行 `.venv/bin/python -m romance.server --port 0`。

默认文字模型为 `qwen3.8-flash`，可用 `ROMANCE_MODEL` 覆盖。配置凭据有三种入口：

- 使用仓库根目录 `.local/local-settings.json` 引用外部百炼 CSV；也可用 `ROMANCE_CREDENTIALS_FILE` 指向该 CSV。字段模板见[配置说明](../../config-examples/README.md)。
- 普通 API 可同时设置 `DASHSCOPE_API_KEY` 和地域一致的 `DASHSCOPE_BASE_URL`，地址以 `/compatible-mode/v1` 结尾。
- 套餐路由使用 `data/qwen-route.json`，引用仓库外的套餐密钥文件。游戏与 Studio 分别配置；显式套餐路由无效会报错，不自动回退普通 API。TTS 与 Vidu 仍使用各自配置。

不要将真实凭据写进代码或提交 Git。默认数据在 `data/game.sqlite`，排版、推进和运行设置也留在本机忽略目录。启动器不替你准备账号或云端资产。刷新或重启可读回聊天、评论、票数和成绩；重启后纯文字自动推进默认关闭。

## 用模拟评论玩文字版

1. 打开工作台的「本地调试」（`/?debug=1`），点「开始第一期」。这一步使用真实文字模型生成成年人物与女生开场；模拟的是参与者，不是模型调用。
2. 在「本地模拟评论」新增或切换用户，发送建议。同名用户由不同稳定 ID 区分。征集结束后最多四条入选，每个作者最多一项；候选箱可看处理状态与已有理由。候选记录不等于最终入选。
3. 投票期发送 `1`、`投1` 或 `投 1` 等当前有效编号。重复投不加票，截止前最后有效票覆盖旧票。批量投票按钮生成明确标记的模拟用户。
4. 可手动推进，也可勾选「本期自动推进」、设置征集和投票秒数。正常回合结果展示后进入下一轮；纯文字自动推进只覆盖本期，终局后手动换期。单次最多运行 20 分钟，到限不再启动下一步，已生成中的步骤会完成。
5. 评论流显示原文、接收阶段和回执，正式消息在完整聊天中回看。发送超时可「重试上一条评论」，保留事件 ID 和原窗口；编辑后重发是一条新事件。

关窗、生成中或跨阶段到达的评论不补计入建议与投票，仍可用于人物互动。旧事件重试不会移到新窗口重新计票。完整玩法、榜单和来源归属见[游戏说明](../README.md#当前玩法)。

## 数字人与正式直播

先启动同级 Studio，再启动游戏；预览与 OBS 的命令见[根目录说明](../../README.md)。正式工作台的「开播准备.command」还依赖本机 OBS、虚拟摄像机、BlackHole 与直播伴侣，使用前完成各自配置。

1. 保存授权房间的公开直播页链接或数字号。点击平台「开始直播」后，服务端探测并至少隔 5 秒复核同一场次，再自动接入。
2. 点击「启动数字人」创建计费云会话。普通口播优先回应本场真实评论，空闲时生成简短话题。
3. 点击「开始游戏」，等待已开口台词收尾后创建新一期并切换游戏镜头。点击「结束游戏」或自然胜负后返回口播；人物、播放器和正式采集连接跨模式复用。
4. 正常下播在直播伴侣操作。工作台确认本场结束后停止本场采集、请求结束数字人并回读云端结果。平台状态未知时仍需核实，必要时点击「结束数字人」。网络失败或刷新本身不代表下播。

调试页另保留自动跨期联调：单次跨轮跨期统一最多 20 分钟，页面每 5 秒发心跳；页面关闭或心跳失联会触发超时停止。优先点「停止联调」并等待停止状态，不能用关闭本机服务代替云端结束确认。

启动显示检查旧会话、等待播放器、创建云会话与等待舞台等阶段。旧场未确认结束或创建请求结果不明时，先核实云端状态，不反复点击开始。正式台词优先于闲聊；闲聊不延长投票倒计时。低头输入动作发出后公开男主消息，女生回信显示等待提示，再同时公开正文与分数。实际音画和动作自然度需看接收端。

## 节目输出与排版

节目页为 `/static/obs-output.html`，画布 1080×1920，包含游戏和数字人；`/overlay` 仅含透明游戏组件，不另嵌播放器。OBS 模式由节目页接收数字人，工作台显示构图参考；预览模式由工作台接收。不要同时打开多个接收端争用同一会话。

「预览排版与遮挡」可调边距、人物位置与宽度，人物保持 3:4。设置由本机服务保存，工作台与 OBS 共用。画幅对照的外框为完整竖屏，内框为 851×1848 手机居中裁切范围；抖音参考图为合成界面，只辅助排版。请用目标手机检查活动卡、弹幕、长消息和底栏遮挡，用 OBS 与观众端分别核对声音。

## 免费造型试玩与真实换形

「开始免费试玩」只在节目和剧情空闲时开启，用本地图片、短片及内存分数从 50 分演示跨档。模拟加分／减分每次 12 分；退出清空，期间不能启动收费数字人，不会记真实礼物账本。

真实换形需六个可驱动资产、匹配底图和音色及两支 HTTPS 转场，按 [Studio 绑定说明](../../ai-live-avatar/studio/EXTERNAL_APPEARANCE.md)配置。设置房号、礼物 ID 与分界后，在连接采集前保存，已有连接须先断开再重连；已开始的一期沿用开场配置。程序以换形请求写出、转场保护期和接收端健康新帧确认进度，但不能识别画面中的具体脸，首次必须目测。

### 一钻手测

只在自有或授权直播间测试。小心心 `463` 为正向、抖音 `164` 为负向；以真实事件单价与数量为准，礼物不计投票，造型值与亲密度独立。

1. 配置有效 DyHub 登录态并开播，用一条可辨认评论核对房间和实收。[登录指南](../../dyhub/docs/cookie-guide.md)
2. 连接采集前启用真实礼物。仅上述组合时，可先不勾「已核实」；程序只接受单价确为 1 钻且来源、数量可靠的事件。若只免费核量，保持真实收礼关闭，在「一钻手测核量」查看独立测试分。
3. 启动数字人并开始游戏，普通档就绪后从 50 分开始。累计 10 个小心心应到 60 并进入精致档，10 个抖音应回到 50。核对工作台账本、OBS 与观众画面；事件条数不等于连击礼物件数。比对后才勾选数量「已核实」。
4. 更换礼物必须填写真实数值 ID，重新核对单价和数量。计分为单价×同组新增件数，同组重发不重复计分。

收礼关闭时标「未计分」，启用但本期不可计分时显示「—」，不沿用上期；预览始终标为预览。初次使用相关功能会在游戏 SQLite 库创建礼物收据与连击表，旧记录保留。

## 故障与验证

模型超时、非法结构或发送失败会暂停并保留进度。内容字段校验失败可自动修正一次；再次失败则停止。重试保留票数、骰子、合法来源和已有消息。请求超过本地 200,000 字节时不自动裁剪投稿，同样输入重试无效，应结束本期或调整输入规则。

「最近本地性能记录」用于查看模型与发送耗时，不是观众实际听见的时间。错误清理分别记录原因和结果。发送成功、RTC 接收、视觉动作、录制、平台播出及云端结束是不同证据；本机显示发送完成不能代替其余核验。
