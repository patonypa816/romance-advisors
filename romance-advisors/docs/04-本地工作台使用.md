# 本地游戏工作台

这是一套本机游戏应用，支持纯文字游玩与真实数字人自动联调。文字模式只需要本机Python环境和现有百炼凭据；自动联调会按本机配置启动数字人服务与云会话。它不采集真实抖音评论，不对外监听。

## 启动与停止

双击项目目录中的 `启动游戏工作台.command`。它会打开已有实例，或在 `127.0.0.1` 的空闲端口启动一个新实例；不会复用或关闭别的项目服务。

双击 `停止游戏工作台.command` 停止本项目的实例。聊天、分数和榜单保留，下次启动后继续读取。中途生成被打断时，工作台会提示重试；不会自动重新请求模型。

首次安装或换电脑时，在本项目目录执行：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m romance.launcher
```

开发时可前台启动：

```sh
.venv/bin/python -m romance.server --port 0
```

Python需要3.11或以上。本次实际使用的解释器及依赖版本见验证记录。

本机游戏和数字人 Studio 的文本模型均使用 `qwen3.8-flash`，通过 Token Plan 专属端点调用；凭据只引用 Servers 中已有文件，不复制进项目。显式套餐配置无效时会报错，不自动回退普通 API。`qwen-audio-3.1-tts-flash` 语音合成仍沿用原通道和凭据。2026-11-04 的真实回合结果见[Token Plan 与支招筛选验收](../artifacts/token-plan-selection-20261104/验收记录.md)。

## 一键数字人自动联调

1. 打开工作台，在「本地模拟评论」上方设置征集／投票秒数并保存；开始联调后，这些设置由联调管理，暂时不可修改。
2. 点击顶部「开始自动联调」。后台启动数字人服务与云会话，准备播放器后自动开场；只点一次并观察状态即可。本节目当前定版角色为「咖啡馆里的温柔凝视」，资产 ID 为 `1015851675149152256`，音色为 `longtian_v3.1`。更换机器后先核对 Studio 的资产和音色。
3. 手机预览右侧人物区域出现真实播放器。浏览器可能要求首次点击画面内播放器的音频按钮才能有声音；按钮保留在播放器中。页面上的服务就绪或发送状态不代表已经出声。
4. 你只需在「本地模拟评论」切换用户、发送建议，投票阶段发送“投1”至“投4”或使用快捷投票。系统自动完成「征集 → 编选 → 投票 → 发送数字人短反应 → 聊天与结算 → 下一轮／下一期」。正常终局后自动生成下一期，本场榜单继续累计，无需逐个点击结束征集、结束投票或换期。
5. 点击「停止联调」停止自动发送并结束数字人云会话。停止完成后，可重新调整秒数或继续纯文字游玩。运行期间手工推进、重试、技术结束与新场操作会禁用，以免打断自动流程；模拟评论始终可以发送。

每次联调跨轮、跨期统一最多20分钟，不会换期重新计时。工作台每5秒发送一次独立心跳；关闭页面或心跳持续失联后，后台会超时停止联调并结束云会话，普通状态读取不会续期。主动结束时优先点「停止联调」并等待停止状态；不需要停止整个本机工作台服务。

遇到游戏或数字人发送错误时，停止继续发送并显示原因，已发生的聊天、评论、票数与成绩保留。先观察停止状态和错误，不通过反复开始或刷新重发旧台词。

启动时会分别显示检查会话、等待播放器、创建云会话、连接数字人和等待舞台等阶段。旧场未确认结束、凭据或形象配置异常等阻断会直接显示原因；只有播放器尚未连接时继续等待。连接建立前即失败会记录为未创建；请求已经发出而结果不明时仍需核实云端，不能直接重试。2026-11-04 已验证真实启动进入第一轮征集并正常停止，详见[启动修复验收](../artifacts/startup-repair-20261104/启动修复验收.md)。

自动联调时，男主会在征集、投票等空档按现场材料考虑说一句短话，也可以沉默；正式短反应与等待互动都可带同次生成的眼神、表情、局部动作和收束。它不会因为聊天暂停收票或延长倒计时，过时内容直接跳过；投票期间保持中立。先观察是否接对对象、催促是否过密、动作收住后情绪是否还在。男主说完本轮选择后，用一组固定无声动作表现发消息。视线先移向桌面下沿，低头输入的 S 指令成功发送时，左侧聊天区公开本轮消息。收尾 Q 发完后游戏继续生成女生回复。手机留在画外。女生准备回信时，左侧聊天显示三个跳动的点。程序从开始生成回信起至少等 2.4 秒，再一起公开正文和本轮分数。它沿用新版G/E前导、主动S短动作与Q收束；Q只发送眼神和表情，与GE一样不发送肢体动作，需要明确返回时写入主动S，发送完成不代表人物已经归位。读弹幕的固定S0与独立待机动作库另按各自配置执行。通用无声表情创作尚未启用；实际低头幅度与自然度仍需人工试播判断。

回复入口不再限制当前轮、当前阶段或游戏回执是否“过期”；编选、措辞和等待女生回复时也能独立准备，有真实评论优先接话。游戏busy只表示主剧情正在生成，不代表人物必须沉默；正式台词仍优先，尚未公开的正式消息不进入互动输入。

闲聊会在三类内容间自然穿插：符合人设和心情的随口碎念、回应真实评论、回应已发生结果。程序区分两种用途：催投稿/催投票只在对应阶段有效，仍核对完整发送预算；普通碎念只依据人物、公开聊天、分数和结局，允许跨阶段及同一期下一轮，事实变化、换人或停止就撤掉未开口的内容。普通碎念不带阶段倒计时或实时票数，不催参与；两种用途都不播即时参与数量或名次，不为内容另加分类模型。

催参与在窗口仍足够时提前准备；是否足够参考最近6次实际创作/准备时长与发送预算，冷启动暂用本场已观察的5.5秒准备、9秒发送估计。这个估计只决定是否创作催参与话术，时间不足仍可创作普通碎念，不再使用剩余11秒/5秒的统一禁止门槛。每次通常10—25字，催参与尽量8—18字，不报精确倒计时；内容格式仍有原60字上限。

下一句可在当前讲述时准备，发送仍须等当前声音与动作完整收尾。正式台词优先撤掉尚未派发的闲聊；已派发任务协作取消，已经开口的短句自然结束。1—3秒自然停顿与音频后的4秒收尾等待重叠，已等足就不再追加；既有动作间隔不变。8秒结果展示不再成为普通碎念的发送截止，同一期下一轮可继续准备或说完；若即将换人，等待已开始的一句完成后再换期。失败或沉默后仍等4—6秒再试。

表演稿读取已知字段，忽略无关额外字段；保留必需字段、真实评论来源、动作部位兼容、各字段长度和SSML校验。移除字段全部合规仍会触发的200字符合成总长限制，动作短语出现次数按原文连续出现理解，再转换到Studio内部编号。不会偷偷删除动作或SSML。格式失败在工作台状态和server.log记录具体field/code及安全长度等元数据，不保存模型失败正文。

每期开场生成人物卡时，通过关注点、遇事反应、句式和表达节奏体现性格差异，保留职业、经历、冲突与情境中的幽默，不依靠固定开头、口头禅或反复的职业术语。此要求用于后续新建的人物卡，不覆写已经生成的人物与剧情。2026-11-04本次改动先完成离线验证，需两端正常加载新版后生效；真实听感与停顿收益仍待短场验证。

当前只核验发送队列与本地发送状态。「发送完成」表示本地发送步骤完成，不能证明云端画面、声音或动作已经完整播放。真实连续4轮发送、聊天结算与停止已验证，具体样本与边界见本文末尾的联调验收记录。透明叠层不嵌入第二个数字人播放器，OBS与真实平台接入另行验证。

## 纯文字模式：用模拟评论玩完一期

1. 点击“开始第一期”，真实模型生成成年人物、背景与第一条女生消息。已有故事可直接“开始下一轮征集”。
2. 在“本地模拟评论”切换或新增模拟用户，发多条评论。昵称相同仍是不同用户；身份由本地稳定ID区分。
3. 征集阶段，非投票口令先作为建议候选；同一用户的多条评论分别保留，先识别有效建议，再按每人最多一个投票选项编选；后发闲聊不会覆盖先前支招。模型在征集结束后选0—4条；能直接作为男主回复的短句、反问和接梗也可入选，不因缺少“你应该”等建议格式被当作闲聊。问候、围观和无关闲聊仍排除；关系早、容易翻车或不符人设不会取消相关建议的资格，不为每条评论单独请求模型。没有适用建议时男主自拟继续。候选收件箱显示入选状态与原因，并区分模型未选、重复合并、未送模型和旧记录缺少结果；模型理由缺失时明确提示。每次最多附加20条模型理由，不保证超过此数的候选都有模型解释。
4. 投票阶段发完整的“投1”至“投4”（允许首尾空白），或点击快捷选项发送同样的评论。一人一票，最后有效票生效；重复投不增加票，非法选项不清旧票。批量按钮创建明确标为模拟的独立用户，显示实际计入与未计入数量。
5. 在评论区顶部勾选“本期自动推进”，设定征集／投票秒数并保存。系统按倒计时编选、收票、生成双方回复与亲密度，正常完成后停留8秒再开下一轮。仍可用上方按钮手动推进。
6. 评论流可看本轮、指定轮或全场，显示作者、原文、接收阶段和回执。候选不代表已入选，最终选项看快捷投票区；当前有效票从服务端记录读取，刷新不会多算。男主女生的正式剧情在“完整聊天记录”回看。

生成期间、非开放阶段、已截止或跨阶段到达的评论会留下回执，不补入游戏窗口，但联调中的人物仍可回应。本期未回复评论可跨轮继续考虑，按内容是否仍值得接话选择；旧回答过时后可以根据新剧情重写，换人物后不带入上一期话题。发送超时后可“重试上一条评论”，沿用原事件ID与发送窗口；编辑后再发是一条新评论。

纯文字模式的“本期自动推进”仅覆盖当前一期，终局后关闭，下一期仍手动开始。每次开启最多自动运行20分钟，到限后不再启动下一步，已经在生成的步骤会完成；不改剧情或强判输赢。技术错误暂停推进，可重试当前步骤。刷新读取原状态；重启恢复聊天、票数、评论和成绩，但自动推进默认关闭。

最强榜按有效采纳后的加分次数/采纳次数；狗头榜按减分次数/采纳次数。零变化只计分母，女生未完成有效回复与评分的技术失败不计成绩。改选其他观众项时归实际作者，自拟不挂作者。换期保留本场榜单；新场才切换累计范围，旧场记录仍在存档。

## 9:16预览与透明输出

- 工作台上方预览固定为9:16；直播输出以1080×1920为设计坐标，等比适应浏览器源尺寸。
- 数字人区域是**宽3、高4**，位于中上部。未联调时显示辅助框；联调时仅在工作台这个区域嵌入一个真实播放器，宽高与排版设置同步。独立透明叠层仍不包含数字人播放器。
- 左侧竖向手机框只展示双方正式发出的聊天消息，顶部显示人物名与亲密度；男主的回复思路保留在数字人口播，不插入手机聊天。投票阶段也保留双方消息；最新女生回复自身比聊天视口更长时，在该回复范围内往返滚动，头尾停3秒，减少动态效果时分段跳转。手机与右侧人物下方共用两列两行投票栏，最多四条一行摘要，同行保留编号与票数；投后只留实际项并显示作者。双榜在投票下方右下区域，以窄栏展示。工作台保留完整聊天与投稿。
- 阶段状态缩小放在手机顶部右侧，不再独立展示节目大标题。手机聊天、投票及双榜有可读底板，其余区域透明。棋盘、参考线和平台遮挡示意只存在于工作台预览。
- 点击“打开透明叠层”获得单独 `/overlay` 地址。后续作为OBS浏览器源时设置1080×1920；此阶段没有验证实际OBS/抖音接入。

“预览排版与遮挡”中可调整四侧边距、数字人位置与宽度。宽高保持3:4，并限制尺寸避免挤出下方组件。排版保存于本地服务，单独浏览器或后续OBS浏览器源读取同一份设置，不依赖共享浏览器缓存。

默认试排边距为上300、右48、下568、左48源像素；左手机(48,300)、456×840；右人物(528,360)、504×672。下方投票区(48,1160)、984×192，两列每列两项，正文28源像素。摘要通常8～10字、尽量不超过12字，原建议全文仍参与男主决策。两榜各首位在右下(712,1372)、320×240，允许次要信息遇到稀疏弹幕；左下密集弹幕区留空。用户已接受右上活动卡与人物头部附近重叠，聊天在左侧避开该卡。内容底边距可调560～640，并为下方投票保留至少176高。这些是可调的设计起点，**不是抖音官方通用安全区**。已查阅的[直播伴侣官方指南](https://streamingtool.douyin.com/docs/guide_dual)提供布局能力，但未提供可用于保证所有手机无遮挡的统一数值。真实手机的客户端、弹幕、按钮与裁切仍需后续开播前检查。

## 模型、保存与故障

默认模型为 `qwen3.8-flash`，关闭思考输出，采用JSON结构化返回；程序独立校验来源、票数、终场分数和消息关系。模型负责剧情，程序负责保存事实。

优先读取 `ROMANCE_CREDENTIALS_FILE` 指向的现有百炼CSV；此电脑也可沿用既有项目保存的凭据文件引用，不复制密钥。也支持同时设置 `DASHSCOPE_API_KEY` 与地域一致的 `DASHSCOPE_BASE_URL`。不要把密钥写进代码或提交Git。

默认游戏数据在 `data/game.sqlite`，排版及推进设置分别在相邻文件中；均已加入Git忽略。开启新场只切换统计范围，旧场记录保留。每轮正式男主消息唯一，女生回复与分数在一次数据库事务中保存。

纯文字模式遇到模型超时、非法结构或服务失败时，工作台显示错误并提供“重试当前步骤”；票数、骰子、已合法确定的来源及已发消息保留。语义上是否忠实、剧情是否自然仍需试玩判断，不能只凭JSON校验保证。

完整模型请求超过本地200,000字节限制时，会提示相同输入重试无效，并禁用该步骤原样重试；本轮不会自动裁剪投稿或改变参与规则。工作台的「最近本地性能记录」可回看编选、措辞、女生回复、发送与公开阶段的耗时；这些是本机记录，不能当作观众实际听见的时间。停止失败时，操作者状态分别保留原始原因和各清理步骤结果，避免后续清理错误覆盖首错。

本次已完成真实数字人连续4轮发送、聊天结算与停止，见[联调验收](../artifacts/avatar-integration-20261103/验收记录.md)。模型字段缺失等内容校验失败会按同一期/轮/阶段自动修正一次，沿用已定来源、票数和台词；女生修正不会重发数字人。再次失败或网络/存储/发送错误则停止，最后错误保留在操作者状态。
