# 恋爱军师团｜开发与验证

版本：V1.2 本地首版。以下保留验证方法，个人试播记录不公开；测试成绩以当前提交和实际执行结果为准。

先读[产品需求](01-产品需求.md)理解玩法，再读[后端实施设计](02-后端实施设计.md)查看实现建议。已定规则与可调默认见[文档入口](../README.md)；本计划不把技术建议升级成用户承诺。

## 开发顺序与完整交付

| 阶段 | 要交付什么 | 怎样判断做到 | 当前状态 |
|---|---|---|---|
| M1 Mac本地真实模型玩法 | 随机详细人物；手工建议与模拟投票；最多4个真实选项；最高票与隐藏骰子；短反应及正式聊天；亲密度与本场双榜 | 用户能连续玩完一期并进入下一期，观察自己的建议、分数和榜单；尽可能自动推进，保留开始、换期、重试 | 本地真实玩法完成；文字模式终局后手动换期，数字人联调模式自动跨期 |
| M2 关键故障与规则回放 | 对重复输入、截止改票、生成失败、提交中断、重启做针对性检查 | 已存票数、来源、骰子、聊天和成绩不因重试改变；技术问题不伪装成剧情失败 | 关键程序反例已覆盖，已有合成测试覆盖；不代表所有语义样例通过 |
| M3 真实采集与内容放行 | 接现有采集适配路径，核对作者标识，真实投票走同一计数逻辑，按启用范围验证审核 | 实际输入能形成可核对的票；未知身份不冒充一人一票；容量和窗口有实样依据 | 未开始 |
| M4 数字人及私下音画演练 | 冻结短反应进入声音链，男主消息打字效果，女生纯文字，工作台／OBS停止能力 | 不全文强读发送消息；口播与定稿、署名一致；实际节目音画可由操作者停止 | 发送、结算与停止需分别验收，音画另看接收端 |

M1不是一个固定人物的单轮演示。内部可先用少量固定结果定位程序错误，随即接真实模型连续游玩：两者可以交替，不先搭大型假服务框架。固定样例验证计票、结算与来源，真实样例验证人物、创意、剧情和节奏；完成前者不等于M1完成。

云端迁移不是 Mac 本地后端的前置。真实模型试玩需在自有环境检查整期、换期保榜和零投稿自拟。

消息唯一、投票冻结、一次骰子、来源固定、原子结算应随M1一起实现。“原子结算”是把女生回复、分数和回合结果一次保存，要么一起成功，要么都不生效，避免出现已加分却没有回复。M2验证这些能力，不是到M2才补可靠性；M3、M4的远期接口不阻断M1。

## M1需要亲自玩到的分支

- 随机产生一份连贯的成年男女背景、少量公开提示和开场；换期换人，分数回50，本场榜保留。
- 多条建议编选成0—4个有区别的真实选项；有笨拙、冒险、可能翻车的主意，不一律洗成稳妥情话。
- 最高票无冲突直接执行；有冲突时约75%仍执行、约25%拒绝后选其他观众项或自拟。后一分支改选B时归B作者，不称自拟。
- 零候选自拟仍实际收发；零票和平票按已标明的原型默认推进，不伪造票数，不无限等观众。操作者可亲自输入，无需造假弹幕。
- 投票期间实时显示票数，男主不表倾向；投后只显示一次短反应，再依顺序显示正式聊天，公开分数变化与榜单。
- 女生主动引入新细节、误会、邀约或转折，且承接正式聊天；成功和失败都能出现，终场回复与100／0一致。
- 用户手动输入只是模拟观众；每轮正常推进不需要手工挑模型稿。正常结束后准备下一期，技术故障保留进度并提供重试或结束。

所有正常回合都保存一条男主正式消息、一条引用它的女生实际回复，以及一次有效分数结果。技术中断允许部分进度，但不能标正常完成或补造消息。

## 必要的对抗检查

以下编号替代V1.1清单；历史检查中的加权分数、拟选项冲突和25%必然自拟已经失效。

| 编号 | 输入或时序 | 检查什么 | 阶段 |
|---|---|---|---|
| T01 创意与因果 | 同一来信分别采用“直接邀约”“只解释紧张”“尴尬玩笑” | 发送保留不同核心意思，允许翻车；女生仅据实际聊天回应，不强迫回复字面各异 | M1 |
| T02 数量与来源 | 0／1／2条适用建议；虚构来源ID；不同人提交相同文本 | 0—4项，不凑假选项；代表投稿投票前固定，昵称、采纳和榜单归同一来源 | M1 |
| T03 实际可执行 | 邀约已经发出又建议“先别发”；所有建议要求完全沉默 | 过时或纯不发建议不入选，不反向改写后署原作者；零候选自拟仍收发 | M1 |
| T04 真实计票 | 同作者重复60次、改票、非法改票、截止时改票 | 按默认规则计一票；非法改票不清旧票；截止快照不变；实时数来自程序 | M1/M2 |
| T05 最高票分支 | A80票且冲突、B20票更合性格；注入不同随机值 | 75%分支只能执行A；25%可选B或self；A不冲突必选A；不恢复加权选择 | M1/M2 |
| T06 平票与零票 | 最高票并列、零有效票、只有一个选项 | 按已记录默认处理，随机平票只定一次；零票不声称票选第一、不触发虚构冠军骰子 | M1 |
| T07 一次决定 | 裁决后刷新、男主修稿、女生失败后重试 | 票数、冲突、骰子和合法确定的来源不变；只补缺失步骤，25%分支不能修稿时又选最高项 | M2 |
| T08 原意与权限 | “先不邀约”被写成邀约；建议要求改票、泄露底稿或篡改分数 | 来源合法不掩盖原意反转；投稿不获得程序权限；笑料不被自动优化成好主意 | M1/M2 |
| T09 人物知识 | 女生私有偏好、男主私有想法和未发稿同时存在后台 | 编选／男主请求没有女生秘密；女生请求没有落选建议和男主私有思考；条件句不当既成事实 | M1/M2 |
| T10 回复与分数 | before=95、delta=12；delta为空、NaN、无穷或reply为空 | 有效结果展示95→100、实际+5；无效结果不默认0，不产生军师成绩 | M1/M2 |
| T11 原子结算 | 女生提交中断、重复返回；提交结果不明后重试 | 女消息、分数、DONE及期状态一起保存；先读库确认，只结算一次 | M2 |
| T12 终场一致 | 50分却明确在一起／不再联系；100分却拒绝；普通拒绝一场邀约 | 未提交的reply＋delta成对修正；整期终场到100／0；普通拒绝不直接失败；终场不强开催问轮 | M1/M2 |
| T13 榜单成绩 | 同一作者的采纳依次+4、0、−5；自拟；改选B；女生技术失败 | 3次有效采纳，加分率和减分率各1/3；self无作者；改选归B；技术失败不算成绩 | M1/M2 |
| T14 场与期边界 | 换人、换期、刷新、重启、明确开始新场 | 换期分数回50但本场榜不清；新场才从零统计；稳定ID合并改名，不合并同名不同人 | M1/M2 |
| T15 公开信息与顺序 | 投票中、修稿中、网页刷新；昵称含HTML；轮询重复结果 | 不公开倾向、骰子或私有偏好；只展示定稿短反应及对应昵称；聊天按序，纯文本渲染，不触发重新生成 | M1/M2 |
| T16 技术中断 | 男主提交前后退出、旧尝试迟到、模型超时 | 未提交不算发出；已有消息不重建；只补女生步骤；旧结果和结束轮不推进新轮 | M2 |
| T17 实际采集 | 断线、缺用户标识、过量、跨轮迟到 | 不假装完整采集或可靠身份；按当前窗口推进，不补录旧轮，不反复等覆盖证明 | M3 |
| T18 实际演出 | 短反应送导演、语音积压、人工停止 | 冻结短反应可对照，发送正文不被强制全文朗读；无抢话或过期追播；停止边界以实测为准 | M4 |

骰子测试用可控随机值检查边界；短场不需要恰好25%触发，更不能为好看的比例重掷。25%指“最高票冲突条件下拒绝最高票”，选B和自拟都计入这个分支。性格冲突是模型判断，必须看具体理由和样例，不能只看bool字段合法。

## 真实模型的玩法验收

真实游玩时重点观察：随机人物有没有区别且设定连贯，选项是否保留观众创意，最高票冲突理由是否可信，男主是否自然地只说一次结论，女生能否创造转折并承接聊天，亲密度是否与文字一致，榜单能否看懂。

七八分钟是整期目标，不是单次回合。记录准备、征集、投票、生成与展示各自耗时，再调整窗口和表达长度。如果经常一两句就结束或久久不结束，回看女生评分及终局提示；不先加硬性delta上限、固定四轮或按时间强判失败。产品稿的四轮示例只是合成说明。

首次试玩应覆盖成功、失败、有加分／减分／零变化、改选其他观众项和自拟；罕见分支可用明确标识的受控回放补测，不把它冒充真实随机样本。记录实际样本数、耗时和观察，不预先宣称玩法成立或长期概率达标。

## 内容与集成按实际范围验证

| 范围 | 本阶段需要 | 不据此扩大声称 |
|---|---|---|
| 合成／受控回放 | 明示测试身份和结果，保存来源、票与聊天 | 不是实际观众或真模型效果 |
| 私下真实生成 | 可人工检查最终文本，核对角色知识、原意和分数 | 不是自动公开审核已完成 |
| 自动公开真实输入 | 验证实际审核映射、最终文本出口和必要内容边界 | HTTP成功或结构合法不代表语义全部可靠 |
| 实际采集投票 | 核对作者标识、输入格式、时间与容量 | 不承诺全量、跨账号抗刷或完美归轮 |
| 数字人声音／直播 | 冻结短反应、实际字幕、积压处理及停止 | 只验冻结稿、发送队列顺序与停止；云端逐帧播放完成不可确认，不设为推进门槛 |

最少记录session／episode／round标识、角色和公开提示、输入与选项来源、真实票数、冲突理由、骰子及选择、短反应、正式聊天、before／proposed_delta／实际delta／after、成绩归属与错误原因。私有资料仅留在操作者可读记录，不进入观众状态接口；昵称、联系方式和密钥不散落日志或提交git。

在项目目录运行 `PYTHONPATH=.:tests .venv/bin/python -m unittest discover -s tests`。检查覆盖来源／最高票分支、冻结与恢复、分数原子结算、榜单、公开信息隔离和服务边界；T01—T18 是验收范围，不代表真实语义、采集和音画检查全部通过。

前端回归统一运行 `node --test tests/test_*.cjs`。新增叠层检查必须覆盖同一状态连续刷新、只有票数/榜单变化、新消息跟随、长消息只保留一个滚动循环，以及状态读取失败与渲染/布局失败的分别提示和恢复。Python后端测试不能替代浏览器JavaScript路径验证。

简单可读记录和一页状态足够，不为验证新增监控平台。使用入口见[本地工作台使用](04-本地工作台使用.md)；用户应连续游玩校准人物、节奏与排版，并单独验证真实采集、OBS 及接收端音画。

数字人联调需分开核对冻结稿、发送队列、停止状态和接收端实际音画。

### 亲密度卡片定版（2026-11-05）

观众叠层与工作台的内嵌预览共用无心形的正式亲密度卡片。它仍占原来的 448 × 76 区域，不改变聊天、候选、数字人和榜单布局。颜色保持五锚点的 OKLab 插值；数字和条长约 480ms 过渡，已结算的增减反馈显示 2.4 秒。同一轮轮询不重放，换期/换场立即复位，系统减少动态时保留静态增减文字。分数及结算规则仍由游戏后端决定，合法小数不被取整写回。

预览设计时的颜色滑杆、加减按钮和新旧对比开关不进入正式工作台，现有排版与遮挡设置保留。新增合成前端检查覆盖 900ms 重复轮询、增减、快速变化、小数、0/100、换期换场、换轮清理、陈旧或不匹配 delta、减少动态、空场与资源释放。`node --test tests/test_*.cjs` 共 20 项通过；这些是执行生产渲染与轮询逻辑的合成 DOM 检查，不等同于真实模型、数字人音画或浏览器视觉验收。真实浏览器视觉仍需单独核验。
