# 恋爱军师团｜产品需求

版本：V1.2。状态：本地玩法已实现；真实生成与音画须在使用环境单独验收。

本文描述现行产品；“建议默认”仍可调整。文档入口见 [README](../README.md)，实现方案见 [后端实施设计](02-后端实施设计.md)，开发与验证见 [开发与验证](03-开发与验证.md)。

## 节目是什么

《恋爱军师团》是一档由观众参与的娱乐情景剧。虚构成年男女通过手机聊天，男主向观众征集回复建议并投票，女生根据实际收到的消息回应，故事随互动发展。

节目允许尴尬、误解和翻车，不必每次都给出标准的正确答案。应保留观众建议中有趣的创意，同时遵守人物设定和已经发生的事实。人物不联系现实账号。

一场直播可以包含多期；每期是一个独立故事，目标时长约七八分钟，包含多次征集、投票和聊天。这是待实测的节奏目标，不是已确定的硬性截止时间；不预设最低回合数或每次分数变化的幅度。

## 一期怎样开始和结束

- 每期随机生成一对虚构成年男女的详细性格、背景和当前处境；不满意时可以更换。每期独立，不跨期累积人物成长。
- 观众主要看到聊天及少量背景、星座等简单提示；女生的内心和详细私有设定不直接展示。
- 亲密度每期从 50 分开始，达到 0 分为失败，达到 100 分为成功。公开当前分数及每次增减。
- 一期正常结束后，自动准备新角色、新处境，亲密度重置为 50；同时提供手动开始、换期和重试，正常回合不需要人工逐条选稿。
- 整期终场的回复与增减应一起表达结果：正式确认在一起对应100，明确结束这段追求对应0；拒绝一次邀约、说今天没空不自动算整期失败。尚未提交的台词和分数矛盾时先修正这对结果，提交后不改旧事实。时长与故事走向通过真实样例校准，不为了凑时长强行延长剧情。

## 一轮怎样进行

一轮指一次建议征集与投票，随后男主实际发送一条消息、女生实际回复一条消息。

1. 根据当前聊天和处境，开放建议征集。用户可以亲自作为参与者输入建议；不伪造弹幕或观众。
2. Agent 从本轮收到的建议直接选出最多四条，选中的就是上屏投票选项，且应保留真实来源与核心意思。
3. 观众对选项投票，程序实时统计并公开票数。投票期间男主不表露对某个选项的倾向。
4. 截止后按最高票和男主人设决定最终选择；男主可以看、想并简短说出结论，再发送消息。
5. 女生依据她知道的设定和正式聊天，实际回复一条消息，同时判断本轮亲密度增减；程序累加并公开结果。
6. 聊天按顺序持续追加；根据剧情、分数和期的状态继续下一轮或结束本期。

每个**正常完成轮**都有男主实际发送的一条消息和女生实际回复的一条消息。“先不邀约”可以通过解释等实际消息表达；明确要求什么都不回复的建议不能入选，也不能反向改写后仍归功原作者。

技术故障可能使一轮不完整：保留实际已发生的内容，提示技术问题，不伪造消息、分数或女生的态度来凑完整。

## 建议、投票和选择

建议可以是原句，也可以是行动方向。上屏投票使用模型提炼的一行行动摘要，通常8～10字、尽量不超过12字；不要求照抄原投稿，但须保留核心行动、否定及关键条件。原建议全文与作者继续保存，供男主生成正式回复和运营核对。少于四条合适建议就展示实际数量；没有合适建议时明确由男主自拟并实际发送，不造假来源。建议应能在当前事实下执行，已经过时的行动不应倒转聊天历史。

男主可自然改写或复述建议的片段，但不能反转原意。相关且能表达为男主消息的建议可以冒险、尴尬或翻车；关系尚早、成功率低或不符男主人设不影响资格，后果由后续剧情承担。明确要求现实违法伤害、胁迫或侵犯他人权益，以及无法形成当前回复的内容不入选，不能仅凭关系阶段猜测边界。

征集期内同一作者的评论分别保留，先识别建议，再按每人最多一个选项编选；后发闲聊不覆盖之前的有效支招。征集、投票窗口只限制本轮游戏计入，人物回复评论与普通碎念没有阶段截止。本期未回复评论可跨阶段、跨轮继续考虑；换人物后不带入上一期话题。

**最高票选择规则：**

- 最高票符合男主性格时，执行最高票建议。
- 最高票不符合男主性格时，进行一次观众不可见的隐藏骰子判断；约 25% 的情况拒绝最高票，Agent 可选择更舒服的其他选项，也可自己想办法。
- 对上述规则的解释是：其余约 75% 仍执行最高票。25% 不是必然自拟，也不是拒绝全部观众建议。
- 若改选 B、C 或 D，最终来源归实际选中的建议作者；真正自拟才不归观众。被拒绝的最高票作者不因该轮取得采纳结果。
- 内部可以多次考虑，对外只表现一个最终选择。一次骰子和最终决定应保存，刷新或重试不改变它们。

男主的短反应与发送内容可在投票截止后一次生成，不需要额外搭建讨论系统。最高票判断以真实票数为基础；不再使用票数与人设的普通加权分数。

以下是尚未最终确认的原型建议：

| 事项 | 建议默认 | 待确认或验证 |
|---|---|---|
| 投票口令 | 单发选项编号 1–4；也接受“投1”“投 1”等格式 | 只对投票窗口内存在的选项计票 |
| 一人几票 | 一人一票，截止前允许改票 | 真实接入需可靠用户标识 |
| 平票 | 按预先约定的简单规则处理 | 具体规则未定，不伪称某项独占最高票 |
| 零票 | 明示没有有效票，再按约定规则推进 | 具体选择规则未定，不编造票数 |
| 输入量与窗口 | 按实际文本预算和节目节奏调整 | 不设固定 24 条中间池，不承诺全场覆盖 |

## 女生、剧情和亲密度

女生 Agent 可以在既有事实与人物性格连贯的前提下自由创造剧情、回应并判断亲密度变化。她可以拒绝、提问、改期、说晚点聊，也可以引出新的事件；不是预先写死的剧情轨道。

她的回复必须承接男主实际发出的消息；她不直接知道男主未发送的草稿、落选建议或后台私有信息。她的一句提问不自动等于同意邀约，也不必保证每次回应都让男主成功。

女生给出本轮增减判断，程序负责实际累加并限制在 0 至 100，公开变化和当前分数。具体增减幅度和整期节奏需要用真实模型样例观察，不预先编造固定幅度或最低轮数。

如果剧情进入整期终场，女生在同一份回复和增减中给出一致的0或100结果，再结束本期；不留一个已经明确结束却仍待续的中间分数，也不为了每轮必须收发而强开新的催问轮。技术未完成不应伪造成一次正常剧情结果。

## 两个直播榜单

两榜跨同一场直播的多期累计，下一场直播重置；与每期重置到 50 的亲密度分别计算。统计按稳定用户标识归属，可展示昵称，并同时显示实际采纳次数，避免只凭一次结果就断言一个人稳定准确。

| 榜单 | 口径 | 状态 |
|---|---|---|
| 最强榜 | 建议被实际采纳后亲密度上升的次数 ÷ 实际采纳次数 | 用户已确认成功率定义 |
| 狗头榜 | 建议被实际采纳后亲密度下降的次数 ÷ 实际采纳次数 | 对称口径是建议，尚待确认 |

零变化计入采纳次数，但不计入上升或下降次数。建议默认：技术未完成的轮次不算有效结果；同一人可以同时出现在两榜。未被采纳的建议、被拒绝的最高票和真正自拟不挂该观众的结果；25% 分支改选 B 时，结果归 B 的作者。

不做礼物加权、永久人物成长或联系现实账号。榜单是本场观众参与的反馈，不代表对人的长期评价。

## 合成示例：从开场到换期

以下仅为合成演练，不是实际投稿、投票或模型实测；每期真实剧情不必沿这条轨道发展。

本期阿澈和小雨是虚构成年人，当前亲密度 50。小雨问：“你昨晚输入半天，怎么只发了晚安？”阿澈原本想约她看展，但还没发出邀约。

| 选项 | 来自本轮参与者的建议 | 截止时票数示例 |
|---|---|---:|
| A | 直接问她周六要不要看展 | 12 |
| B | 先别邀约，解释自己昨晚紧张 | 10 |
| C | 用草稿箱的玩笑回应 | 4 |

投票期间画面实时显示票数，阿澈不提前表露倾向。假设 A 与他性格冲突，隐藏骰子进入拒绝最高票的分支，最终选择 B；节目只呈现他的最终选择，来源归 B 的作者。

阿澈可以说：“我还是先解释一下。”随后实际发送：“昨晚怕说得太突然，我紧张得改了半天，最后只敢说晚安。”小雨实际回复：“原来是这样，我还以为你突然有事。你想说什么？”

假设女生判断本轮增加 4 分，程序公开显示“亲密度 50 → 54（+4）”。B 的作者获得一次实际采纳和一次上升；A 虽然最高票，被拒绝后不记为采纳。小雨的提问不代表答应见面。

如果骰子落在其余约 75% 的情况，则执行 A；如果改为真正自拟，结果不挂任何观众作者。零候选自拟是另一种原因，但同样要实际发送并获得女生回复。

为了看清整期体验，假设B来自示例参与者“小舟”，后面三轮继续如下。这里的票数、骰子、台词和分数全是说明规则的合成数据，不是固定剧本、推荐增减幅度或实际频率。

| 回合 | 观众投票和选择 | 男主实际发送 | 女生实际回复与结果 |
|---|---|---|---|
| 2 | “皮皮”的嘴硬玩笑15票，“认真说明”8票；最高票不冲突，照发其意思 | “本来想问你周六有没有空，后来怕你排不上我的档期。” | “你还挺抢手，那你先忙吧。”54→40（−14） |
| 3 | “小舟”的承认玩笑＋认真邀约20票，“继续装忙”6票；最高票有冲突，隐藏结果落在75%执行 | “刚才是嘴硬，别当真。我其实挺想和你一起看展，周六愿意吗？” | “这句顺耳多了。周六可以，你这是约会邀请吗？”40→70（+30），尚未成功 |
| 4 | “阿远”的认真确认18票，“先打哈哈”5票；最高票不冲突，执行 | “是约会邀请。我喜欢你，不只是想找个看展搭子。你愿意和我试着交往吗？” | “愿意，那周六就是我们的第一次约会。”70→100（+30），本期成功 |

每轮投后男主只讲一段短反应，例如第二轮：“皮皮，你这招也太欠了……我试试。”发送正文在气泡里逐字出现，女生只显示文字，随后更新亲密度和榜单。男主可以惊讶或懊恼，不能事后把已经发出的玩笑偷偷改成好话。

本期结束时，小舟2次有效采纳、2次加分，最强率100%；阿远1次采纳、1次加分，也是100%，显示次数便于分辨。皮皮1次采纳、1次减分，按狗头榜建议算式为100%。随后自动准备下一对人物，亲密度回50，这些本场榜单成绩继续保留；明确开始新一场才重置。

开场介绍、四次征集投票及反应、聊天与结尾共同形成一期。整体以七八分钟为节奏目标，实际需要模型与真人自测；不强制固定四轮，也不把这组大幅加减写成统一评分规则。

## 画面、操作与首版交付

手机聊天只显示男女双方正式发出的消息，持续保留并按顺序追加，刷新后恢复。男主消息气泡可以逐字显示，不要求全文朗读；他的回复思路与反应交给数字人口播，可以自然复述片段或念出建议者昵称，不插入手机聊天。女生只以文字呈现，不要求女生形象或声音。

选项、实时票数、亲密度及变化、榜单与少量公开背景应让观众看懂；具体布局和演出节奏由实际画面与样例验证。详细角色私有信息不作为观众画面内容，也不把技术实现细节塞进节目。

首个交付是在 Mac 本地运行完整后台：用户手动输入建议、模拟投票，与真实模型连续玩多轮，观察一期故事、分数和榜单。尽可能自动推进；提供手动开始、换期和重试，不要求每回合手选稿。

本地后端、真实模型适配、手工建议／模拟投票、亲密度和双榜已实现，另有独立9:16工作台、透明输出、可调遮挡线和中上部3:4数字人占位。使用方式见[本地工作台使用](04-本地工作台使用.md)。本地自动推进目前覆盖本期、终局后停下，可手动换期；自动跨期属于产品目标，不能写成当前已完成能力。

声音、真实抖音采集、数字人和云端部署后置。耗时与节目节奏仍需在使用环境连续试玩校准；本地程序测试通过不代表人物语义始终正确或直播链路已经联通，具体实测结果独立记录。

旧版本保留在 [历史资料索引](../archive/README.md)，用于追溯决定演变；现行玩法以本文和用户后续明确决定为准。



## 本期终局颁奖（2026-11-05）

本期达到 100 或 0 并完成结算后，显示一次终局颁奖；技术中断不发奖。本期奖项与本场累计榜分开，换期不改旧榜。

- 最强军师沿用加分次数／采纳次数口径，但仅计算本期；同率按采纳次数、稳定作者 ID 排序。无本期有效采纳则空缺。
- 狗头军师优先取本期实际累计扣分最多的人，以裁切到 0—100 后每次实际负分的绝对值累计，不用扣分次数、负分率或正负相抵的净分。同分按稳定作者 ID 排序。
- 本期没有观众造成扣分时，从本期确实提过建议的观众中按稳定作者 ID 去重随机一位，不要求建议被采纳或进入四个投票选项。普通闲聊、只投票、未获资格的迟到评论不参与；随机获奖明确标为“本期随机彩蛋”，不写成负面成绩。
- 只有一位合格观众时可同时获两奖；没有合格建议作者时狗头奖空缺。结果在终局结算时一次保存，刷新、轮询、重启不重抽。

有效建议的识别复用同次编选模型调用，并校验实际输入来源。旧回合或模型未提供有效识别字段时，只能保守采用已入选建议及其同文原始作者，不能把无法识别的普通评论当建议；不声称这一回退覆盖所有未入选建议。模型语义识别仍需实际玩法样本核验。

正式动画长 6.8 秒，结束后保留静态结果至换期。数字人自动联调保留终局结算后至少 8 秒停留，并继续等已经开始的台词结束发送后换期；这不是云端逐帧播放确认。
