# 恋爱军师团｜后端实施设计

版本：V1.2 本地首版 · 日期：2026-11-03 · 状态：本地核心、SQLite、HTTP工作台与真实模型适配已实现；整期及换期试玩已完成，新增数字人定稿发送与自动节目入口，真实联调结果见验证记录；真实采集／公开审核未接入。

玩法与决定状态见[文档入口](../README.md)和[产品需求](01-产品需求.md)；实现次序与验收见[开发与验证](03-开发与验证.md)。本版本取代旧加权选择方案；投票细则、节奏与榜单排序等建议可按实际样例调整，不从历史稿恢复旧规则。

## 1. 首次交付与职责边界

首次交付是在Mac本地运行整个后端：控制台手动输入建议和模拟票，真实模型连续完成多轮情景剧，网页持续显示聊天、票数、亲密度和本场榜。手工输入明确属于自测，不编造真人投稿填空。目标尽量自动推进，保留开始新场、换期、重试和技术结束等少量操作。

当前实现为单进程Python应用、SQLite和独立网页工作台，数据默认保存于data/game.sqlite；未实现PostgreSQL兼容层。不建多Agent编排、消息集群、用户平台或长期人物成长系统。

程序负责真实计票、隐藏骰子、状态、来源、分数累加和榜单统计；模型负责人设生成、建议理解、剧情和对白。模型不直接改票或数据库。真实采集、OBS与云端部署后置，不作为本地文字版前置条件。声音通过可选的数字人联调模式接入。

每一正常完成轮必须有一条男主实际发送消息、一条女生实际回复。允许笨拙、误会和翻车，不把所有创意洗成标准情话；没有合格稿或服务失败则记技术问题，不伪造聊天，不设正常hold／no_reply路径。

## 2. 一场、一期间的人物与剧情

一场直播使用一个显式建立的`session_id`，包含多期情景剧；刷新、重启和换期都不等于新一场。榜单按整场累计，只有明确开始新场才重置。

每期调用模型生成成年男女的详细背景、人设、共同背景、女生私有偏好、可公开的少量背景／星座提示和第一条女生来信，检查后一次保存。一期内固定底稿，下一期重新生成或更换，不记录跨期成长。开场来信是种子消息，不算某一轮的女生回复。

女模型可以自由创造后续剧情，不依赖预写正确路线；新细节写入正式对话后成为本期历史，不悄悄改写已经发生的消息。女生输入包含她的人设与私有偏好、共同背景和正式聊天，不含男主私有思考、投票后台或落选建议。

编选与男主调用仅取男主人设、男主可知的共同背景和正式聊天，不能直接传整个episode底稿。女生的私有偏好不进入这些请求；观众可见的星座等提示也不自动成为男主知道的事实。每次请求显式挑选所需字段即可，不需要额外权限服务。

公开端只取已选的少量提示、聊天、选项／票数、分数和榜单；不把详细私有偏好或隐藏骰子传给观众。男生气泡打字、短反应与女生纯文字显示是呈现方式，不改变正式聊天。

每期亲密度从50开始，100成功、0失败。女生生成整期终场时，同一份reply＋delta必须把正式在一起或明确结束追求分别表达为100／0；拒绝单次邀约不等于整期失败。约7—8分钟指整期含多轮的目标时长，尚需连续实样校准；不设强制delta上限、最低轮数，不硬改分数凑时长。提前自然结束可自动换期；目标时间到了但未到0／100，不仅凭时间判胜负。

## 3. 最小状态与冻结点

一期用`PREPARING / ACTIVE / SUCCEEDED / FAILED / TECH_ENDED`等简单状态即可；生成失败就停在技术候场，不启动一份半成品人设。ACTIVE同一时刻只运行一轮。

| 回合阶段 | 工作 | 冻结或持久化 |
|---|---|---|
| COLLECTING | 以当前聊天为问题收建议 | 开轮时固定问题／聊天输入；关窗时固定建议范围 |
| SELECTING | 直接编选0—4个真实选项 | 编号、原文来源、摘要、各项性格冲突bool及理由 |
| VOTING | 展示实际选项和实时票数，不表采纳倾向 | 截止时保存每人的有效票与汇总 |
| DECIDING | 看最高票及其冲突判断，执行本轮隐藏骰子 | 最高票项、冲突、骰子和分支 |
| DRAFTING | 按允许分支选定来源并生成短反应、该句TTS语气、消息正文 | 来源一旦合法确定就保存；短反应、语气与正文验证一致后一起定稿，修稿不重新选择 |
| WAITING_REPLY | 文字模式直接继续；联调模式先把冻结短反应按序发完，再公开男主消息并生成女生reply＋delta | 发送任务与定稿绑定；女消息、分数前后值、有效结果同事务保存 |
| DONE | 正常收发及结算完成 | 保留历史，继续下一轮或结束本期 |
| ABORTED | 技术／操作结束轮，保留实际进度 | 原因；不接收迟到写入，不冒充正常完成 |

0个有效选项跳过投票与冲突骰子，明确自拟，随后仍实际收发。故障记录发生阶段、原因和能否重试，候场期间不自动从头重演。整体可自动推进，重启则先展示未完成阶段并读取已有记录，再补缺失步骤。

“先不邀约”可发解释，“不继续追问”可发体谅的确认；“完全不回复”不作选项，不能反向改写后署原作者。女生拒绝或说晚点聊是实际回复；不应立即反复催问，允许剧情转场或收束。明确要求不再联系的终场不强开下一轮；若生成开场就禁止任何回复，应更换开场而非违背它硬发。

## 4. 建议收件与投票默认

当前本地工作台统一使用 `POST /api/comments` → `Game.accept_comment(event)`。网页自动携带 `event_id、author_id、nickname、text、expected_round_id、expected_phase`；操作者不用填写轮号。每条原文、服务器接收时间、场／期／轮、接收阶段、处理结果和关联建议／票一起保存，重试同一事件返回原回执，不在新窗口重新处理。同ID不同原文报冲突；跨轮或阶段到达的评论不补计入游戏，但本期评论仍可进入人物回复池。自动倒计时截止在接收处检查，避免调度器切阶段前误收。

征集阶段先把非完整投票口令作为待判断候选，编选模型再排除问候、围观和无关闲聊；不是逐条调用模型。投票阶段只认完整“投1”至“投4”，其他评论不计票但仍可被人物回应。生成、终局和未开场时仍可记录评论，但不参与建议／投票。评论回执与实际建议／票一次事务保存，失败一起回滚；忙时收件不打断正在等待的模型步骤。

这些边界利用本地网页的发送窗口信息。未来真实采集无法仅靠语义可靠识别跨轮迟到，仍需按实际事件字段验证；不强制真实观众报轮号或承诺全量采集。

有可靠消息标识时按来源去重；作者使用稳定ID，昵称仅用于展示和朗读，同名不合并、改名不变新人。缺可靠作者ID不能声称“一人一票”，但不妨碍受控用户本地自测。采集故障不能解释成真实无人投稿。

征集期内每条评论独立保留为待判断候选，不按作者覆盖；同一次编选先识别建议，再按每个作者最多一个投票选项取舍，后发闲聊不抹去已有支招。完全重复文本可减少重复输入，但保留真实来源列表。需要一个代表投稿时，建议选保留列表中最早收到者，投票前冻结其source_proposal_id与作者；短反应昵称、聊天归属和榜单都用这一来源，不在结算时临时挑作者，也不先做多人分账。普通量整轮交模型，不设固定24条中间池。预算按实际上下文扣除角色、聊天与输出空间；时间到或预算到提前关窗是可调建议。

若突发积压仍超预算，只作一次按文本预算的截取／固定种子抽取，记录实际输入范围；提前关窗偏早到、截取会漏输入，不承诺全场代表性。不先建立多级模型筛选平台。

投票细则仍是建议：独立窗口只认完整“投1”至“投4”，且选项存在；一人一票，截止前最后有效票覆盖旧票。重复投同项不加票，投不存在的项不清空旧票。关票与更新由串行处理／短事务确定先后，截止后快照不再变。

平票建议在最高票并列项中抽签一次并保存，先确定本轮最高票代表；零票建议让男模型从现有选项或自拟中确定一次，不称“票选第一”，不触发不存在的最高票冲突骰子。单选项是否省略投票、窗口长短均可调；实时票数必须来自程序记录。

程序为上屏项分配稳定option_id和1—4投票编号，另存source_proposal_id；投票编号不是投稿ID。选项冻结后不换句话继承旧票，若发现确实不可执行，明确技术结束或按已说明的处理规则推进，不偷偷重算结果。

## 5. 最高票与隐藏25%分支

旧的alpha加权、人设0／1／2打分和综合分择优不再使用。编选调用可在内部对每项返回`conflicts_personality: bool + reason`，程序在关票后读取最高票那一项，不让模型临时重写票数。

最高票符合性格则采纳；不符合则保存一次隐藏随机结果：约75%仍执行最高票，约25%拒绝最高票。25%分支允许男模型选更舒服的其他观众选项B／C／D，或真正自拟，不能把它等同于“必然自拟／拒绝全部”。

75%路径的定稿只能表达最高票的核心意思；25%路径的男主调用可返回`selected_option_id`或`self`及发送文本。选择B就保留B作者归属，不能仍给最高票作者记采纳；self不挂观众来源。只有一项又拒绝它时可自拟。

程序先保存最高票、冲突依据、骰子与允许分支，再调用男模型；男模型只拿允许的选择范围，不需要原始随机值，也不向观众解释抽签机制。获得合法来源选择后保存，后续修稿不得再换来源、重掷或借女生失败重新裁决。内部允许多次考虑，但公开只输出一次结论；不展示隐藏骰子和内部推理，投票期间不提前表态。

性格冲突不同于建议资格。只过滤确实无关、已无法作为本轮回复、不能形成消息或明确要求现实违法伤害、胁迫和侵犯权益的内容，并说明依据；关系尚早、尴尬冒犯、成功率低和不符人设不取消资格，不能把可能不被喜欢猜成已明确的边界。摘要、改写不能反转核心意思。SELECTING的summary用于手机内一行投票，通常8～10字、尽量不超过12字；这只是展示摘要，DRAFTING继续收到original_text全文及真实来源，不能把摘要当作原投稿替代保存。

## 6. 模型调用与分数结算

| 调用 | 输入 | 主要输出 |
|---|---|---|
| 每期准备 | 随机主题／可更换设置、成年角色约束 | 人物、共同背景、女生私有偏好、公开提示、首条来信 |
| 每轮编选 | 男主人设、男主可知共同背景、正式聊天、本轮建议 | 0—4个不同办法、真实来源、冲突bool及理由 |
| 男主结论 | 真实票数、保存的分支与来源约束、当前剧情 | 非空正文、短反应；25%分支可确定非最高项或self |
| 女生回应 | 女生人设／私有偏好、正式聊天、当前分数与男消息 | 非空reply、有限数值delta，可附内部简短理由 |

不为“讨论”增加评委或自治角色；男模型可以内部考虑，前端仅播短反应与最终结论。反应可提作者昵称、局部复述建议，不必全文念男生发送正文。

delta由女模型根据男生回复合不合她心意提出，代码只验证类型、有限数值及当前步骤，再计算`after = clamp(before + proposed_delta, 0, 100)`。实际变化`delta = after - before`，公开展示新分数与实际增减，不把越界部分也显示成已加减。

正式女生回复、before／proposed_delta／实际delta／after、回合DONE及episode分数／状态必须在同一事务保存。重复回复、轮询和重试不再次结算；女生技术失败没有有效成绩，不先改分后等消息。

缺delta、非数值、无穷值或空reply属于无效输出，不能默认为0分后计入军师成绩。若技术重试成功，最终只结算这一个有效结果；先前失败尝试不增加采纳次数。

达到100／0分别成功／失败，台词需与结果吻合；若出现100分却明确拒绝、或中间分数却已明确整期终场等矛盾，先用同一女模型修正尚未提交的reply＋delta，再统一提交一次，不新增评审Agent。修正以同一个before为基准，候选结果不先计分，已提交的聊天和分数不回滚。语义吻合靠提示、样例和必要修稿，不声称程序能完美证明。

女模型的自由剧情允许误会、转折与失败；不把分数低自动改写为技术错误，也不为凑7—8分钟悄悄抹去delta。修稿、零选项和其他异常的具体回放见[开发与验证](03-开发与验证.md)。

## 7. 最小持久记录与事务

口播语气与表情动作和台词同次生成和保存：模型依据本期男主人设与聊天给出 `reaction_instruction` 与 `reaction_expression`，游戏加入熟人聊天的共同风格后，冻结成一段完整表演。首版至多一个动作组，包含台词锚点、局部动作、眼神、表情和保留余韵的收束。TTS后的现有定位模型按真实字时间安排发送；没有合法排程时不偷偷删动作冒充成功。语气不作为正文朗读；重复任务按完整表演和截止时间判等，不额外调用一次情绪模型。旧存档缺字段沿用旧自然语气，已发生台词不回填改写。

正式反应和等待互动可在同一次生成中给出可选 `ssml`，最终只冻结在 `plan.segments[].ssml`；`text` 仍为游戏与字幕正文。Studio统一验证XML字面正文与定稿完全一致，TTS接收标记文本，数字人Type10接收明确或同次词时间证实的朗读文字。`instruction`描述整体情绪，SSML提供明确停顿与整段韵律；模型默认只稀疏使用`speak`与`break`，不额外调用模型。正文与已知展开读法遵守原短句字数预算，SSML另限8192 UTF-8字节。

当前已接通`speak`的rate/pitch/volume、`break`、`sub`、`phoneme`、`say-as`。基于当前3.1 Flash实测，同一段的韵律属性同步映射为HTTP参数；多个`speak`只有有效参数一致时可用，不同参数明确拒绝，避免静默忽略。改写读法的区间暂不作为动作锚点，普通短语仍使用同次PCM的真实全局词时间；停顿不在动作层重复累加。缓存绑定完整SSML、声音与解析版本；普通文本和旧记录无需补写SSML。实际范围和样本见[SSML接入验收](../artifacts/ssml-integration-20261104/验收记录.md)。

等待阶段的现场互动由 `AmbientPerformance` 管理：合并近期评论、阶段开放／临近截止／安静时段和已提交结果，给同一个内容模型少量公共现场与最近六次已发表演。女生私有偏好、未提交结果、隐藏骰子和投票选项领先情况不进入输入；投票中台词和动作都要求中立。模型可保持沉默；互动不修改正式聊天、分数或采纳归属。普通互动可在人物已准备完毕的编选、措辞、等待女生回复等阶段独立准备，不受game.busy或8秒结果展示窗口限制。评论优先于催参与和无声低头。只读取public_state中已公开消息，不让已保存但未播出的正式选择泄露。

每次只准备一个可选短段，与正式稿共享一个发送锁，不建立积压队列。生成互动不占用游戏busy，收评论、计票和关窗继续；正式稿撤销未开始的互动，已开始的短段完成必要收束后让出发送器。催参与才绑定对应征集／投票截止和完整发送预算；普通碎念／回评论只绑定人物和公开剧情事实，不因换阶段或同一期换轮作废。事实改变可撤销未开口回答，原评论仍可结合新事实重新考虑；只把真实已回答的评论标记完成。换人、停止或模型超时会撤销待播内容，旧期话题不套到新人物，发送窗口所属期也参与迟到请求的隔离。取消请求回执丢失则查询同任务，必要时幂等取消一次；发送结果仍不明或已部分发送失败时停止联调。冷却与近期记录只保留在本次节目内；措辞阶段保留一次空闲无声低头机会，之后仍可回复评论。

直播session只需显式ID和轻量开始／结束信息，先不建完整账号系统。结构化配置、选项、裁决和定稿可存JSON，不设独立素材发布账本。

| 记录 | 最小内容 |
|---|---|
| episode | session_id、人物／背景、私有偏好、公开提示、开场、当前score、状态、起止时间 |
| round | episode_id、问题、阶段、选项／来源、冲突判断、冻结票数、最高票、骰子／分支、最终来源／定稿、分数结果、尝试与错误 |
| proposal | round_id、来源消息ID／接收ID、稳定作者ID、当时昵称、原文及顺序 |
| vote | round_id＋稳定作者ID唯一，保存最后有效选项与接收顺序 |
| chat_message | 有序ID、episode_id、round_id、角色、正文、parent_id；开场seed标识 |

男主消息每轮唯一；女生对男主parent_id唯一，并校验角色／本期关系。下一轮引用已有女生消息，不重复插入来信。DONE不仅检查“至多一条”，还需确认一对消息和分数结果确已保存。

网络调用不放事务内。保存男主消息与转WAITING_REPLY同事务；女生提交另用短事务同时结算。数据库提交结果不明先读库，再决定补哪个步骤，不能先生成另一版或重新加分。

骰子与分支仅在尚无结果时写入；步骤结果核对轮号、阶段、尝试标记。重试更新尝试，旧结果迟到不能覆盖；ABORTED不再接受写入。男主提交后出错只补女生步骤，已有消息、来源和骰子不变。

首版不需要outbox、任务租约、复杂暂停恢复或多目的地发布队列。技术结束保留真实消息与无效成绩标记，可显式换期；换期score回50但session不变。手动文字模式的自动推进仍仅限本期。数字人自动联调由一个Program负责跨轮、正常终局后换期，共用累计20分钟上限；开始联调从新一期起步，保留旧记录和本场榜单。

## 8. 最强军师与狗头军师

最强军师已定口径：本场内`加分次数 / 采纳次数`。由round结果按`session_id + 稳定作者ID`聚合即可，不新增排行榜平台。

仅“采用该作者建议＋女生回复和delta有效保存”进入分母。实际delta正则加分次数＋1；为0则分母＋1、分子不变。未采纳、真正self、女生技术失败均不算成绩；25%路径选B是B的成绩，不是最高票作者的成绩。

狗头军师榜推荐对称用`减分次数 / 采纳次数`，实际delta负记一次减分；此具体算式仍是建议，不冒充用户已确认。榜单同率先采纳次数多、再稳定排序也是建议，界面同时显示次数，避免1次100%被误读为长期实力。

一期换人、分数归50不清榜；刷新／重启也不清。新场显式创建session_id才从零统计。昵称可更新展示，不作为分组键，零采纳者不显示虚构成功率。

## 9. 网页、采集、导演与发布边界

| 拟定适配函数 | 职责 |
|---|---|
| `accept_comment(event)` | 本地手工评论走同一建议／投票逻辑；按发送与接收窗口校验，未来采集需另行验证 |
| `get_public_state()` | 返回持续聊天、定稿短反应、公开提示、选项／实时票数、分数与本场榜；不泄露私有偏好／骰子 |
| `Program.prepare / perform` | 将确定的短反应直接交数字人现有TTS与发送队列，不重新决定聊天或来源 |

表中是职责边界；当前Game核心与HTTP工作台已实现收件、状态读取和操作入口，冻结短反应经数字人的私有external入口进入现有发送链。网页采用轮询，消息按已保存ID追加与恢复；男气泡以完整已保存正文渐显成打字效果，刷新不重新生成或重发。女生仅文字，不强制shown回执、逐条停留或SSE。

最终短反应与男主消息一起保存后才进入公开状态，按round_id呈现一次；本地文字首版直接显示这段反应。来源昵称从冻结投稿读取，self不感谢某个观众；修稿中的临时反应不提前展示。数字人模式使用同一份短反应，不另做一次角色选择；按owner_id、generation和round_id绑定任务，重复提交返回既有任务。男主消息可先保存，但只有发送队列确认sent且send_complete后才公开并调用女生回复。停止或换期后的迟到回执不推进旧轮。

昵称、选项和聊天按纯文本渲染，不执行其中的HTML或链接；公开分数与实际增减不意味着公开女生内部理由、私有偏好或完整推理。页面恢复只读取记录，不触发模型调用。

现有[dyhub客户端](../../ai-live-avatar/studio/dyhub_client.py)保留事件id、user.id和时间字段，真实稳定性仍需样本核实；[普通主持流程](../../ai-live-avatar/studio/automation.py)会调用`generate_director`重写内容，不是冻结稿入口。现已增加游戏独占的external路径，屏蔽普通互动和待机动作，不让其抢用同一发送队列。

私下自测可人工检查最终文本，固定合成样例可用测试审核；假审核不能用于自动公开真实输入。真实公开前按启用能力验证审核、最终版本出口和音画停止，不要求完美自动语义，也不以媒体双闸阻塞本地文字玩法。

当前Mac本地后端、数据库、真实模型适配及独立工作台已落地；核心、模型边界、HTTP工作台和启动器自动化测试覆盖核心、评论与HTTP链路（最新数量见开发与验证），真实连续玩法已完成一整期及换期检查。9:16预览中的3:4区域可嵌入唯一数字人播放器，透明叠层仍只输出游戏画面；OBS和实际直播尚未验证。启动和游玩见[本地工作台使用](04-本地工作台使用.md)，实测记录与开发安排见[开发与验证](03-开发与验证.md)。

云端逐帧播放完毕无法确认，也不是推进条件。完成只依据本地指令发送队列的顺序与发送回执，云端画面交给模型处理。云会话的结束确认只用于停止计费及安全开新场，与台词画面是否播完是不同问题。



## 本期终局数据与头像边界（2026-11-05）

`episode.finale` 与女生终场回复、实际分数及 DONE 状态在同一个 SQLite 事务中保存。字段为 `episode_id/status/started_at/duration_ms/awards`；`started_at` 是服务端 epoch 秒，`duration_ms=6800`，`awards.best/worst` 为冻结奖项或 null。公开状态顶层返回 `finale`，另计算 `elapsed_ms`，HTTP 状态提供 `server_time`；读取不写库、不抽奖、不调用模型。未终局、技术结束、未保存终局时钟的旧终局均返回 null，不为旧记录补造演出时间。

奖项包含稳定 `author_id`、纯文本昵称、可选 `avatar_url`、采纳和正负次数、实际净分／正分／负分累计，以及 `selection_reason`。最强理由为 `highest_positive_rate`；真实扣分为 `most_negative_points`；无人扣分随机为 `random_suggestion`。累计负分字段 `negative_delta` 保存负数，比较最小值即累计扣分最多。本期随机奖不改变任何 round 的分数、采纳或累计榜。

同次 select 可以返回 `suggestion_proposal_ids`，仅接受实际送入编选的来源 ID；入选项必定进入建议池，文字去重的建议保留各原作者。字段缺失、格式错误或超出输入数量时回退到已入选建议，未知、非字符串来源不会新增候选，也不能改变选项、作者归属或积分。这个识别结果只用于本期娱乐抽奖，不扩张窗口资格，不新增逐评论模型调用。

`/api/comments` 和 `/api/proposals` 接收可选 `avatar_url`，保留在原建议及选项作者，终局按稳定作者 ID 归属；无头像或校验失败不影响评论和建议。URL 只允许 HTTPS、无用户密码、默认端口和已列出的图片 CDN 域名（`douyinpic.com/douyinstatic.com/byteimg.com/ibytedtos.com` 及子域），不做代理抓取，不向模型传递 URL；前端对失败加载和空值显示默认头像。域名白名单是防护约束，不保证所有真实头像域名都受支持。
