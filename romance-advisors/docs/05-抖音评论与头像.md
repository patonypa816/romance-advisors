# 抖音评论与头像

## 已完成与边界

游戏现在可以从本机 DyHub 的 SSE 接入评论，并保留参与征集的观众头像链接。头像不是身份依据；作者和事件以 `roomId + user.id / id` 生成带命名空间的稳定标识，同名观众不会合并。不会下载图片、抓取个人主页、保存原始事件或把头像发给模型。图片缺失、不安全或加载失败时使用默认头像，不阻断建议和评奖。

这次验证使用合成数据和本机模拟 SSE 服务，经过真实 SSE 解析、游戏存储、建议编选、终局评奖。这组适配器测试没有连接真实抖音、运行真实 DyHub 采集、调用模型/TTS/Vidu。随后已将原机器 DyHub 源码独立收录到仓库根目录 `dyhub/`，保留本机修改；依赖、构建产物、Cookie 和浏览器资料未上传。“拉取代码”仍不等于“已经安装或启动采集服务”，实流字段稳定性和头像有效期需受控试播验证。

## 操作

1. 在根目录 `dyhub/` 手动执行 `npm ci --ignore-scripts`、`npm run build`，再运行 `ai-live-avatar/studio/启动评论采集.command`。需要 Node.js ≥20 与 Chrome/Chromium；启动器现在指向仓库内 `dyhub/`，固定使用浏览器内核和 `127.0.0.1:8757`，缺少构建或端口占用就退出，不自动安装、不接管其他服务。只使用自有或已获授权的直播间。
2. 在游戏工作台开始一期。开始剧情仍使用现有模型配置；评论接入不会替你开启游戏或数字人场次。
3. 展开控制区的“抖音评论来源”，填 `http://127.0.0.1:端口`（默认8757）及直播页末尾的纯数字房间号，点“连接本期评论”。不能填主播主页ID或内部 webcast ID。保持游戏、Studio 所属 `ai-live-avatar/` 与 `dyhub/` 同级目录。
4. 活跃本期的有效普通评论持续进入游戏，普通互动与建议/投票资格仍按原有规则分开。开放且未阻塞的征集期，头像随非投票候选记录保留；最终是否属于有效建议由现有编选决定。投票期只有当前存在选项的完整“投1”至“投4”计票；其他评论、生成期间或截止后的评论仍可记录用于普通互动，但不保留头像。入场、礼物、过长/无效/过期评论不写入游戏。
5. 点“停止接收”只关闭游戏订阅；本期结束、技术结束、换期或退出游戏服务也会关闭它。下一期需重新点连接。页面刷新不会新建订阅，服务重启不恢复连接。上游 DyHub 自身可能仍在采集，需要在其控制台由操作者停止。

默认不自动连接；连接参数只保存在本次服务内存，不保存账号 Cookie 或凭据。每期最多接收5000条，达到上限会停止，重新连接同一期不会清空计数。源异常和统计只显示固定错误码与数量，不展示头像URL或原始身份。

## 时间与安全约束

以本机收到评论时的当前回合和阶段处理，复用工作台截止门禁；跨阶段重投同一事件ID仍去重。只接受带有限毫秒 `ts/receivedAt`、不超过45秒、未来偏差不超过5秒的事件；连接前超过5秒的旧事件不补收。上游在缺失源时间时会用当前时间补齐，不能据此保证绝对源顺序、零漏采或严格按平台发送时刻归轮。正式计票前应核对实际版本和真实样本。

头像只允许已有HTTPS图片CDN白名单，限制2048字符，拒绝账号密码、非默认端口、fragment、空路径、SVG及危险协议。不做服务器图片代理；浏览器只加载已通过白名单的头像，失败时回退。链接可能随上游失效，保存链接不是永久图片存档。

本机接口：`GET /api/source`、`POST /api/source/start`（`base_url/room_id`）、`POST /api/source/stop`（空对象）。沿用工作台同源与本机门禁，拒绝跨站及重定向，不支持远程采集地址。
