# 抖音评论、头像与礼物

游戏通过同级 `dyhub/` 的本机 SSE 接收授权房间事件。房号、登录态、账号与资产由操作者提供，仓库不包含真实 Cookie、浏览器资料、事件样本或云端绑定。

## 配置与操作

1. 需要 Node.js 20+ 与 Chrome/Chromium。在根目录 `dyhub/` 执行 `npm ci --ignore-scripts`、`npm run build`，再运行 `ai-live-avatar/studio/启动评论采集.command`。启动器使用仓内 DyHub、浏览器内核和 `127.0.0.1:8757`；缺构建或端口占用就退出，不自动安装或接管其他服务。
2. 按 [Cookie 指南](../../dyhub/docs/cookie-guide.md)在本机配置登录。该快照沿用 Cookie 配置，不提供新版多账号网页登录入口。仅连接自有或已授权直播间。
3. 在正式工作台保存公开直播页 `https://live.douyin.com/数字房号` 或数字房号。手机短链先打开取最终直播页；主播主页 ID、内部 webcast ID 与公开房号不能混用。每次实际开播另有平台场次 ID，用于本场统计与停场判断。
4. 检测并复核目标房间开播后自动接收，口播和游戏共享连接。通过一条可辨认评论核对实际房间与作者。工作台可「暂停本场接收」和恢复；下一真实场次也会恢复。调试页另保留按期手动订阅。
5. 真实礼物需在连接采集前配置并启用，按[一钻手测](04-本地工作台使用.md#一钻手测)核实数量。默认只收评论；礼物走独立账本，不进入建议池、不增加选项票数。

采集器优先使用已保存的自动采集设置，首次可从造型配置中的房号开始。网络失败、SSE 断线或页面刷新不单独触发清榜或云端停场；确认本场下播后才执行归属本场的停止与云端结果回读。

## 评论、计票与身份

- 作者和事件标识分别由 `roomId + user.id / id` 构造命名空间，昵称只用于显示，同名不合并、改名不换身份。需用真实样本核实上游身份稳定性，缺可靠作者标识不能声称严格一人一票。
- 征集期每条合法非投票评论独立保存；编选识别有效建议，同作者最多一项。投票期只接受当前存在的编号，如 `1`、`投1`、`投 1`；同一作者以截止前最后有效票为准。
- 普通互动和游戏资格分开。生成中、关窗后或其他非投票评论可以记录供人物回应，但不补进已关闭窗口。礼物不作为投票。
- 按本机接收时的回合和阶段处理，同一事件跨阶段重投仍去重。事件必须有有限毫秒时间 `ts/receivedAt`，不超过 45 秒、未来偏差不超过 5 秒；连接前超过 5 秒的旧事件不补收。上游缺时间时会补当前时间，因此不能承诺绝对源顺序、零漏采或严格按平台发送时刻归轮。

正式榜只累计可信同一抖音场次收到并被有效采纳的真实建议，模拟输入和无可信场次的历史数据留在调试口径。本地「新开场次」不清正式榜。完整规则见[游戏说明](../README.md)。

## 头像协议与安全

只读 `user.avatar`，不猜测其他字段。头像随符合条件的征集候选、选项作者与终局奖项保留；投票和普通闲聊不另存头像。头像不是身份依据，也不发给模型；缺失或加载失败时显示默认头像，不影响计票或评奖。

头像 URL 仅允许既有 HTTPS 图片 CDN 白名单，限制 2048 字符，拒绝账号密码、非默认端口、fragment、空路径及 SVG；不下载、不做代理、不抓个人主页。浏览器直接加载允许的 URL，链接可能过期，不是永久图片存档。

协议入口见 [events.ts](../../dyhub/src/types/events.ts)、[normalizer.ts](../../dyhub/src/pipeline/normalizer.ts)；归一化按头像缩略图、中图、大图依次回退。来源与修改记录见 [DyHub 配置说明](../../dyhub/README.md)。代码与合成 SSE 测试只能确认适配路径，实际运行版本、实流字段、头像有效期和收礼数量须单独核验。

## 接口与验证范围

本机接口：`GET /api/source`、`POST /api/source/start`（`{base_url, room_id, scope:"broadcast"}`，调试按期订阅可省略 `scope`）、`POST /api/source/stop`（空对象）。接口保留同源与本机门禁，拒绝跨站、重定向与远程采集地址。

合成测试可以经过 SSE 解析、游戏存储、编选和评奖，不代表已经连接真实抖音、启动数字人或完成观众端播放。首次真实接入请分别核对房间、稳定身份、重复事件、截止改票、礼物增量、OBS 音画与停场结果。
