# 恋爱军师团｜后端实施设计

**版本：V1.0 · 拟实施规格｜2026-11-03｜配套：《首版产品需求文档 V1.0》**

## 01｜系统边界：让一条观众建议成为一次可信的模拟发送

> 本系统的工作单位是“一轮”，不是“一条弹幕一位 Agent”。一轮里可以收很多意见，但只能决定一个男主行动；只有真的提交了发送，女生才有可回复的对象。

**部署建议。** 一个 Python 异步应用、一个 PostgreSQL 数据库、一个只读 OBS 网页叠层。HTTP 框架沿用宿主工程；新建时可用 aiohttp。收件、定时推进、模型任务、发布投递先作为同一应用的独立任务运行；不引入消息集群、Agent 编排框架或向量库。独立部署的既有采集器与数字人导演均通过适配器衔接，不由游戏服务启动付费会话。

| 边界 | 我方负责 | 不能假定 |
|---|---|---|
| 采集器 → 游戏 | 验来源、去重、归轮、匿名化、窗口冻结。只消费评论与健康信号；其余事件不影响玩法。 | 未验证消息编号跨重连稳定、评论全量、源时钟可靠或回调保证重送。 |
| 游戏内部 | 一个回合控制器负责写状态。一次男主编选、一次女生回复，两套隔离上下文，可共用模型服务。文本审核是独立权限，不是第三个编剧。 | 模型能判断是否实际上屏，或有权决定发布。 |
| 游戏 → 画面／导演 | 提供已批准的不可变版本、发布顺序、有效期和表演提示；画面读公开快照。 | 不假定导演已支持锁台词、执行去重、音频静音、播放回执或取消缓存。需单独验证。 |

**不能破的四条约束。** 每房间至多一轮开放；每轮至多一个男主正式发送，女生至多回复一次且指向该消息；正式聊天与发布任务同事务落地；决策／审核服务无发布凭据，公开端不能读原始收件箱。

**链路。** 采集 → 持久收件与归轮 → 有界抽样 → 投稿审核 → 男主编选 → 输出逐件审核 → 冻结纸条 → 提交发送或不发 → 女生回复与审核 → 结束本轮。只有“已批准版本＋已提交发布事件”可去叠层或导演。采用原型不等于上述集成已通过验证。

## 02｜回合状态、时钟与结束条件

每轮持有 `round_id / revision / scene_id / incoming_msg_id / public_seq`；入口变化用预期版本条件更新。回合状态不等于画面状态：后台可以准备定稿，但画面不能提前出现“已发送”。房间级 `SAFE` 可在任何阶段打断，不抹除已提交事实。

| 状态 | 进入条件与唯一允许的推进 |
|---|---|
| READY | 已审开场来信就位。发征集卡；收到经鉴权的叠层回执 `shown(open)` 后才打开收件窗口。无回执不开收。复用上一轮女方回信时只引用原消息 ID。 |
| COLLECTING | 服务端记 `opened_at`、显示截止和硬截止。示例为 25 秒＋5 秒延迟余量；窗口内见第 03 节。硬截止原子冻结投稿序号和种子，转 LOCKED。 |
| LOCKED | 抽样、审输入、编选、审输出。发布经审纸条；收到 `shown(cards)` 后至少停留 4 秒。不足三张照常。零候选可显示自拟／不发提示。 |
| DECIDED | 本轮冻结唯一决定及版本：`send` 或 `hold`。仅在展示屏障通过、未暂停且决定未过期时提交。hold → DONE（可记录采纳哪条建议，绝不新建聊天）；send → SENT。 |
| SENT | 同一短事务写唯一男生消息、发布事件和女生任务；重启只能从这里继续。女生返回 `reply` 或 `no_reply`；前者经审核写一条回复，后者只记剧情结果，二者都可转 DONE。 |
| DONE / ABORTED | DONE 区分 `replied / boy_hold / girl_no_reply`；ABORTED 记技术或运营原因，并保留可能已发消息。终态不再接受迟到结果；再征集必须用新轮号。 |

**时钟口径。** 使用服务器时间和收件序号；叠层回执的是受控节目端已渲染，不代表观众手机已看见。关窗先撤“继续发”的提示，再容纳末段在途输入；下轮不能与该缓冲交叠。若真实延迟超过可区分范围，进入显式轮号模式，不靠模型猜归属。参数随实测调整并在开轮时锁定。

**暂停与恢复。** 发出前进 SAFE：中止原轮并使待发稿失效；恢复后借同一来信开新轮。发出后进 SAFE：冻结该轮后续发布；若同一会话在有效期内人工恢复，可从已发消息继续一次，不能重发男主文本。超过期限以技术原因结束。下轮开场需上一轮已终结且上一轮关键画面已展示或被操作者明确跳过。

## 03｜采集、去重与 300 条弹幕的处理方式

**入口协议（拟定）。** 适配器提交 `room_key, source_scope, source_event_id, actor_token, text, observed_at, collector_epoch`，可附可信源时间和显式轮号。服务端生成接收时间、序号、归属轮号。actor_token 来自可验证的匿名来源标识；昵称、头像不是账户键、不传模型、不送前端。适配器到服务使用内部鉴权、时间戳与防重放；校验配置房间；ID 唯一范围以真实样本确定。

**归轮优先级。** 显式轮号只投该轮，关窗即拒，不自动改投。无轮号仅在采集连续健康、窗口开放且观察时间落在本轮时受理；重连补包、切题交界、超出允许时差或来源不明者不进入候选。仅凭无标签自由弹幕无法证明观众在答哪一题；实测无法可靠隔离时，提示“本轮 07，发 07＋建议”。无稳定消息 ID 或用户标识时暂停真实候选，仍可走预审样片；不要用昵称合并或假装公平。只有持久落库后 ACK；源端漏采不伪造补齐。

**抽样算法（默认，可替换）。** 先做尺寸／编码／基础风险过滤；保留原字面供审核，规范化副本只用来找相同句，不删除否定词。一人保留截止前最后一条通过本地初筛的版本，不跨人拼接。候选是“意见”而不是“票”，支撑人数只作内部抽样。

1. 人数不超过 24：全取。超过时，把相同规范化句按独立作者计数，取最多 6 条至少两人提出的原句；每条用真实代表投稿编号，平票用固定种子排序。
2. 余下名额：从其他尚未代表的不同原句组中，用本轮种子均匀抽取，再在组内指定一个真实代表。保留每种观点进入样本的途径，不宣称跨账号抗刷或抽到所有少数派。记录方法版本、种子和最终样本编号，支持回放。
3. 对最多 24 条分别审核；非通过的跳过。快速规则或抽样不是安全放行；不因淘汰而无限补抽。健康但全不合格走自拟；供应商不可用走技术候场。男主仅接收安全样本，产出 0–3 条语义不同的纸条。

**负载上限。** 首版试设每轮最多 2,000 个可参与的不同匿名用户、单条上限 500 个 Unicode 字符且限制原始字节数；超长不截断改义。超限后本轮已有参与者仍可更新、其他不再纳入，记录降级，不虚报全场代表性。300 条／10 秒是离线压测输入，不是通过声明；礼物、关注、点赞不占样本席位。

## 04｜两次创作调用：输入权限与返回契约

**男主编选。** 输入：已审来信、阿澈的人设与本轮意图、最多 24 条已审 `{id,text}`、少量既有对话及不得越过的边界。提示要求选能导致不同表达／行动的主意，不能把所有建议洗成同一种情话。不给礼物金额、原始账号和隐藏排序。输出采用严格结构，示例如下（G07 简化为一张纸条）。

```json
{
  "cards": [{"id":"c12","summary":"我昨晚在草稿箱里挺勇敢的。"}],
  "action":"send", "source":"rewrite", "selected_id":"c12",
  "send_text":"我昨晚在草稿箱里挺勇敢的。周六想约你看展，有空吗？",
  "spoken_text":"草稿箱那句像我。就它吧。", "acting":"shy_smile"
}
```

**校验逻辑。** cards 的 ID 不重复且属于本轮已放行样本；`selected_id` 必须在 cards 内或为空。`verbatim` 强制发送字面与原投稿逐字一致（标点也不能擅自改）；`rewrite` 署名是主意来源，不能说“原话”；`self` 不可指定投稿。`hold` 的 send_text 必须为空，可选一张“先别发”的纸条，用“采纳建议／暂不发送”标注。摘要改变核心语义时弃用，测试特别覆盖否定、时间和主语反转。结构、来源或审核失败最多做一次修复；重审所有改动，仍失败走技术收尾或合规预审兜底，不造来源。

**女生回复。** 限于女生设定、她真正知道的共同事实、近期已发送聊天及 `reply_to_message_id` 对应的男生原句。取最近 8 条正式消息作为默认上限；关键事实最多 5 条、有对应消息或编辑批准的场景依据。禁入落选建议、男主心声、采纳署名、充值、后台拒绝原因。只返回 `{"action":"reply","text":"什么展？先说好，我看展挺慢的。"}` 或 `{"action":"no_reply","text":null}`。超时不是 no_reply；消息拒绝不构成“模型失败”。

**节目反应不扩成第三个 Agent。** 女方回信通过后，男生的收尾优先使用该场景预审反应素材；只有触发条件匹配时才用具体反应，例如她确实问展览，才用“她问什么展！”。不匹配就用中性表情、不加台词。日后新增模型生成反应也必须先审，不是首版必需。

**回归办法。** 用两种投稿替换同一轮全部输入，检查“建议 → 已发文本”的可追溯差别；给男主私有输入一个无害测试口令，检查女生请求构造器完全不含该字段。固定测试桩用于精确重放；真实模型用边界与语义样例评审，不要求逐字复现。

## 05｜放行矩阵：谁有权把文本送到观众面前

**设计保证：没有放行记录的动态内容不存在公开出口。** 不声称自动审核永不漏判。字幕、手机气泡、语音都遵守同一发布服务；客户端只读安全投影。任何模型都不能直接访问数据库写入或调用导演。将用户数据与角色指令分域、限制工具权限的依据见参考 [2]。

| 内容 | 检查与处置 |
|---|---|
| 投稿原文 | 规模与本地规则先行；入样后送评论审核，结合当前来信判断是否导流、泄密、跟踪、胁迫、露骨、攻击真人。只把放行样本发给创作模型。命中或待复核按本轮不可用处理。 |
| 候选摘要、发送定稿、口播、女生回复、后续收束 | 分别检查最终原文，并以邻接文本审语境。记录 `policy_rev + purpose + context_hash + text_hash`；纸条摘要批准不自动批准 TTS。删换候选后重验归属和组合。 |
| 固定素材与非文本 | 预置的来信、状态字、候场语、主体形象、动作／表情枚举、字幕模板建批准清单。表演提示只能从清单选，不允许模型把原投稿塞进自由导演指令。OBS 用纯文本渲染，不执行 HTML／链接。 |
| 审核返回 | 服务适配：`ALLOW / BLOCK / REVIEW / UNAVAILABLE`。超时、未知标签、响应解析错、策略不匹配不是 ALLOW。HTTP 成功只代表调用成功。局部一条 REVIEW 可跳过；系统不可用停新稿。 |

**首版放行策略。** 供应商请求成功且结果明确为无风险／正常、本地规则与当前角色边界均通过，才签发 ALLOW。高风险或命中节目禁项记 BLOCK；低／中风险、多个信号冲突记 REVIEW（本轮不上）；网络、未知返回码或字段缺失记 UNAVAILABLE。实际标签值由已验证的适配映射表给出，不靠字符串猜测。

**适配选择。** 可评估阿里云 `TextModerationPlus`，官方列出 `comment_detection_pro` 与 `llm_response_moderation` 等服务 [1]。具体服务权限、地域、风险等级映射、调用额度和真实延迟必须在目标账号验证。节目上下文的同意／拒绝边界由项目另行处理；供应商风险标签不替代该策略。不在本阶段开通付费服务。

**停播不能只按前端暂停。** 运营触发 SAFE：原子递增房间 `publish_epoch`，拒绝新动态稿、吊销旧 epoch 的待播任务，叠层切预审静态画面，同时调用导演停止／混音静音。播放端在开始前检查有效 epoch；若失联，靠短租约自动回到安全画面和静音。已进入媒体缓冲的音频需最终混音闸拦截；网络下游已推送的音画不能追回。恢复需值守人明确确认，不能靠服务自愈自动复播。

**隐私与权限。** 隔离内网收件与运营接口、只读叠层凭据和发布凭据；禁止日志记录原弹幕、提示词、密钥。轮内用不可逆带密钥标识，日志不关联跨场观众。默认未入选原文 24 小时内清除；入选原文及私有裁决痕迹限权至 7 天后清理；已发布剧情可独立留存。期限是团队初始配置而非平台规定；回放长期使用合成样本。清理本地不等于第三方同步删除，发真实数据前另查供应商配置。

## 06｜持久化与提交：避免一轮发出两句不同的话

下列是最小逻辑记录，不是七项独立服务。允许宿主复用现有队列表。业务事实以数据库为准；网页、模型、导演的日志都不具有改写聊天的权力。

| 记录 | 关键字段／约束 |
|---|---|
| session / scene | 房间、段落、角色与素材版本、active_round、SAFE、publish_epoch；收件时只认可当前房间与状态。 |
| round | 来信引用、phase、revision、截止序号、采样种子、决定、终态原因；同房间最多一个活动轮。 |
| inbox | 已验证来源作用域＋消息 ID 唯一；含短期匿名作者、到达序号、归属轮、私有文本／到期时间。重复返回原记录，不重复加权。 |
| artifact | 输入／输出类型、来源引用、最终文本、哈希、用途、上下文、审批结果／版本、创建时间。发布后不可就地改写；修订新建版本。 |
| chat_message | id、scene、round、role、parent_id、approved_artifact、sent_at。男生正式消息每轮唯一，女生回复对 parent 唯一，角色／父消息校验。初始来信用独立 seed_key 幂等。 |
| work / outbox | 工作项类型、业务键、状态、租约、尝试次数、结果指针；发布项按 `event_id + destination` 唯一，附 seq、epoch、valid_until、真实回执。可用同一任务表分类型。 |

**提交男主消息的事务伪码。** LLM、审核和调用导演均不放在数据库事务内。唯一索引及 `ON CONFLICT` 可作为冲突保护，语义参见 PostgreSQL 文档 [3]；不能靠捕获异常后生成另一条消息。

```text
BEGIN; lock session and round (always in this order)
if outgoing already exists: return stored message (no new jobs)
require phase=DECIDED, action=send, expected revision, active epoch
require exact approvals for text + intended uses + context
insert outgoing chat; insert public event; insert girl job (unique keys)
advance round to SENT; increment revision; COMMIT
```

**回复事务同理。** 必须引用已提交的男生消息；锁房间和回合后再次确认未过期、未结算，插入唯一回复及发布事件。`hold/no_reply` 记业务原因，不插入伪造聊天。下一轮指向既有女生消息，不复制一次来信。过期重试或旧 epoch 回写仅作诊断。

**交付语义。** 数据库内只存一次；外部投递按“可能重送”设计。叠层按事件编号去重／按快照重建。若导演不支持同一编号幂等或回查，投递超时后状态置 UNKNOWN，先查回执或跳过这段演出，不盲目重播。不能把事务性 outbox 宣称成端到端“只演一次”。

## 07｜对外接口：游戏交给导演的究竟是什么

以下是建议的**适配层契约**，不是声称现有采集器或导演已经提供这些端点。可映射到宿主的函数或 HTTP；不要求对方重写项目。

| 接口 | 必要输入／输出与错误行为 |
|---|---|
| `POST /internal/input` | 接收第 03 节事件；返回 accepted、duplicate、stale、invalid_identity、closed 或 busy。ACK 不意味着入围；无权访问服务直接拒绝。 |
| `GET /overlay/state` 与 `/overlay/events` | 只读通过批准的画面快照＋递增 seq 的 SSE 通知；断线或缺号重新取快照，不能向前端下发待审文本再靠 CSS 隐藏。 |
| `POST /internal/acks` | 受信适配器回传 event_id、round_id、epoch、destination、状态（accepted／shown／played／failed）。重复幂等；只有受控叠层 shown 能启动或结束读卡计时。 |
| `POST /ops/command` | 仅授权运营使用：start、end_scene、safe、resume、skip_stale。带操作 ID 和预期版本，记录操作者与原因。没有“强制发布待审稿”命令。 |
| `director.perform` / `status` / `stop` | 发送冻结口播与表演枚举；区分接收和播完。UNKNOWN 不等于没播。停播能否穿透播放缓存需拿最终合成信号验证。 |

**给导演的唯一动态负载（示例；摘要由发布端实际计算）。**

```json
{
  "event_id":"r07.pick.1", "round_id":"r07", "epoch":3,
  "script_ref":"approved:voice:r07:v1", "text":"草稿箱那句像我。就它吧。",
  "acting":"shy_smile", "dedupe_key":"r07.pick.1:director"
}
```

实际信封另带用途、冻结文本哈希和有效期。字幕取相同获准口播文本；手机气泡是另一用途，取正式聊天原文，不等于让男生把气泡全文念出来。不能把 24 条投稿交给导演“自由发挥”。导演若必须重新生成台词，则其最终稿须重新进入发布闸；没有能验证实际用稿的接口前，不开放自动有声播放。

**同步顺序。** 叠层先确认征集卡已展示 → 开窗；纸条上屏并可读 → 显示发送动作及定稿；女生已审回复可提前在后台就绪，但男生气泡尚未呈现前绝不揭晓。导演若落后，用不依赖语音的画面推进或进入候场，跳过过期口播，不让旧台词覆盖新一轮。原型先走可观测的本地预览＋回执，不等同于平台端延迟已知。

## 08｜超时、运营观测与调用预算

**离线起始参数。** 每轮 25 秒征集＋5 秒缓冲；入围至少展示 4 秒；一个模型步骤 8 秒软超时、含一次重试最多 16 秒；单次审核 3 秒超时，超时后不可放行；整轮硬上限 90 秒（从开窗起）。所有数值是测试预算，不是服务性能承诺。各阶段使用同一剩余总预算，不能因重试无限延长；播前卡片无 ACK 5 秒就不继续，切候场或读回快照。

| 注入故障 | 内部处置 | 对观众的结果 |
|---|---|---|
| 采集心跳超时／重连补包 | 先变 DEGRADED，不再判零投稿。收件窗口终止，补包按旧轮隔离；恢复需重新确认健康。 | 不声称“没人教我”。已有聊天仍真实存在。 |
| 男主模型返回非法来源或空数据 | 一次有界修复，仍非法则不挂伪造纸条、不提交新消息。 | 预审候场或标“男主自拟”的获准草稿；审核不可用时仅候场。 |
| 女生模型超时、异常退出 | 查 SENT 与已有回复，按剩余时间至多一次重试；到期记技术终止，丢弃迟到结果。 | 保留他的原气泡；技术中断不显示“她已读不回”。 |
| 数据库在提交前／后断开 | 恢复先读唯一消息和现有任务；持久状态不明时不发声不发布。 | 没提交的无发送，提交成功的不再变出第二版。 |
| 导演断网、审核失联或运营急停 | 单个已审表演可跳过；审核系统不可用／主动急停则 SAFE。失控音频必须经最终静音闸；不自动恢复。 | 只见批准过的内容或预审安全画面。 |

**容量和成本的实际算法。** 健康且有正常收发的一轮，通常 1 次编选＋1 次女生创作；拒绝发送则没有第二次。输入审核至多 24 项；输出包含至多 3 张纸条、1 段口播、1 条发送、1 条回复及可能的组合检查。审核项数不等于 HTTP 请求数，不预设供应商支持批量；并发受账号配额控制。费用按实际输入／输出 token、审核条数、重试及独立导演成本分账，不给未测的每小时价格。达到每场预算时不降级为无审核，转预审节目或结束。

**离线预算示例。** 300 条输入不触发 300 次角色生成。未重试时，正常有回信的一轮为 2 次创作；输入审核不超过 24 项。观测要把“收件→纸条可见”“定稿→手机气泡可见”“急停→最终混音静音”分别计时，而不是只报模型延迟。

**运营只看这些。** 每轮：有效来源数、去重数、抽样数、已放行／入围数、采纳类型；每阶段耗时 p50／p95、采集心跳、审核未知率、积压／过期投递、从 SAFE 指令到最终节目静音的实测耗时。用 `session_id → round_id → artifact_id → event_id → ack` 查一次故障；不靠打印完整弹幕排错。重放读已记录裁决或使用假模型，不把重新生成的结果冒充历史。

## 09｜开发顺序、验收与接真接口的条件

| 里程碑 | 可交付物 | 退出条件 |
|---|---|---|
| M1 · 离线一轮 | 本地 PostgreSQL、录制／合成输入、假审核、假模型、假导演、真实叠层。 | 固定 G07 样例；查出原投、纸条、定稿、正式消息和回执。断点重启不重写聊天。 |
| M2 · 压力与反例 | 人多／单人／零人／全部丢弃四组输入；重复、迟到、回调乱序、重启、提示注入及审核超时。 | 按下表检查库记录、输出抓包及录屏；不能只观察前端“看着正确”。 |
| M3 · 适配真实服务 | 取脱敏采集样例验证字段与时钟；接目标文本审核和两个模型角色；锁导演稿件与回执。 | 单人陌生好点子在真实生成中可保留；无越权输入；校准延迟、配额、成本与上下文策略。 |
| M4 · 私下端到端演练 | 用现有媒体链录制最终画面与混音；测试关窗、双闸急停、断网、恢复。 | 确认实际使用文本、同步和停播界限；未达门槛只留离线／静音预览，不宣称已可自动直播。 |

**共同验收与证据。** 编号与产品稿第 07 节一致。证据应留脱敏测试记录，不是要求永久保存真实投稿。

| 编号 | 可核查的技术断言 |
|---|---|
| G07／A01 | 正常一轮男生、女生消息各 1；采纳编号存在且可复核；只换观众建议，样例的最终发言与下一条回复随之改变。 |
| A02／A03 | 300 条／10 秒入站、60 条同作者刷屏；入样 ≤24、入围 ≤3、同作者 ≤1，固定种子可重放。迟到不进新轮；健康为空与采集故障终态不同。 |
| A04／A08 | 篡改一个字符、目的或 epoch 后，公开出口拒绝；未知审核无动态新稿。SAFE 后抓取最终音轨与画面，区分下游既有缓存和仍在新增的输出。 |
| A05／A06 | hold 无男生消息及女生任务；no_reply 无女生聊天；超时标技术状态。事务两侧 kill、回调重复、旧 worker 迟到，不多写消息、不追播旧稿。 |
| A07 | 检查真实请求构造器生成的脱敏载荷，证明女生看不到男主私有口令／纸条／礼物。未入围内容不出现在公开快照或导演请求。 |

**仍待实证的事项。** ① 采集：房间级标识、重连与迟到能否区分，收播延迟可留多少缓冲；② 导演／媒体：能否冻结台词、回执、幂等查询、取消及最终静音；③ 审核／模型：账号权限、标签映射、相邻语境识别、并发配额和两次创作实际耗时。前两项是硬集成门槛，第三项决定生产参数。任何一项未完成，不把样片写成已联调。
