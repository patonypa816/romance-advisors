## 4. 会给Vidu哪些东西
- Type10：每块完整台词文本，2条。不是把动作标签混进朗读文本。
- Binary：真实TTS音频，24kHz、单声道、signed16 little-endian PCM，常规100ms/4800字节。两块分别867840与871680字节，共1739520字节；末包按剩余音频。
- Type9：本次8组动作，每组GE→S→Q，总24条。GE只有眼神/表情；S包含主动动作及眼神/表情；Q为正常坐姿和目标眼神/表情。

## 8. 本次暴露的调教点
1. 第一轮意图请求约30秒，脑只给49字符，真实语音10.8秒。第二轮改固定稿才控制住内容规模；固定稿的36.24秒不是第一轮意图时长能力的修复证明。
2. 每块原4秒DRAIN加下一块GE前导造成约5秒块间空档。音频已全部预备好仍存在，因此不是TTS网络延迟。
3. 本次上下文要求每块一个简洁动作，模型却每块给了4个。报告保留真实结果，不人为删成一个。
4. 实际生成中仍有复杂G/E过渡描述，例如“短暂看向右侧再回看镜头”，Q含“回到正面平视镜头/恢复平静自然的微笑”；第二段末动作part为head但描述含身体前倾。这些是自然度与字段职责的调教问题，结构通过不代表表演已经理想。
5. 本次未观看Vidu画面，不证明动作是否真能达到或是否与口型自然同步。
