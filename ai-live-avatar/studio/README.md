# Studio 数字人工作台

Studio 在本机接收观众评论与主持安排，请求文字模型生成台词和动作计划，调用百炼 TTS 合成声音，再由唯一发送器交给 Vidu 实时数字人。浏览器通过 AliRTC 接收音画。游戏使用同一 Studio 会话，不为每轮剧情另开云场。

完整安装、凭据准备与 OBS 接法见[根教程](../../README.md)。本目录是当前工作台入口；上游 `ai-live-avatar/server.py` 是另一套入口，其配置不能与 Studio 混用。

## 配置与自己的角色

游戏与 Studio 默认统一读取仓库根 `.local/local-settings.json`：

```json
{
  "bailian_credentials_file": "/ABSOLUTE/PATH/TO/bailian-credentials.csv",
  "vidu_credentials_file": "/ABSOLUTE/PATH/TO/vidu-key.txt"
}
```

字段只引用自己保管在仓库外的文件，不在这里填写密钥。首次从仓库根复制 `config-examples/local-settings.example.json`，按启用功能替换路径；具体命令见[账号配置](../../README.md#2-配置自己的账号)。已有用户正常停场并退出服务后，自己将原引用文件的必要字段迁入新文件，程序不搜索旧凭据或恢复旧机器的运行归档。

默认文字模型为百炼 `qwen3.8-flash`、北京地域、关闭思考，普通 API 路由使用上述 CSV。可选 `data/bailian-brain.json` 只设置 `model`、`region`、`enable_thinking`。自己的 Token Plan 可通过 `data/qwen-route.json` 单独配置；显式套餐路由错误时拒绝调用，不自动回退普通 API。TTS 仍需普通百炼凭据，Vidu 仍需自己的密钥与资产，文字套餐不会替代它们。[占位模板](../../config-examples/README.md)

在顶部「数字人资产」页同步或上传自己的资产，填写角色名称、人设和回复偏好。上传、云同步和资产选择需显式操作；上传不自动开场。空闲时选择开场资产；通用手动直播换形发出后需观察动态画面，再人工确认更新角色上下文。

音色映射位于自动生成的 `data/local.json` 的 `tts_voices`。正常停场并退出后，仅合并自己的「资产 ID → 音色 ID」，保留令牌、端口和其他设置。新安装的兜底音色为 `libai_v3.1`，映射只影响新合成。六档游戏造型另见 [EXTERNAL_APPEARANCE.md](EXTERNAL_APPEARANCE.md)。

## 启动与停止

从 `ai-live-avatar/` 目录执行：

```sh
.venv/bin/python -B studio/server.py --preview
```

根据终端打印的本机地址打开工作台。`--preview` 由预览页独占播放器资格；OBS 输出时正常停场、退出后，去掉该参数重启，再用[根教程](../../README.md#obs-与抖音直播伴侣)的 OBS 节目页接收音画。也可双击 `启动工作台.command` 使用 OBS 模式。服务只监听 `127.0.0.1`，已有本项目实例时打开其地址，不创建第二份；本机控制与播放器令牌不得公开。

页面和本机服务启动均不会自动创建云场。选择自己的角色、核对模型与音色配置后，点击「开始会话」才请求计费 Vidu 云场；接收端音画就绪后处理互动。OBS 录制或公开推流由操作者单独控制。

结束时点击「结束会话」，等云端结束状态回读和录像归档，再双击 `停止工作台.command` 或在前台终端按 Ctrl+C 退出。创建结果未知、停止未确认会阻止下一场；不要删标记或杀进程绕过保护。

## 评论与主持输入

- **模拟弹幕**：按观众身份生成回答，不能取得主持权限。
- **主动安排**：按主持描述生成一轮台词和动作，执行一次后停止。
- **主讲话题**：生成有限提纲并逐段讲述。观众互动优先，无待回应内容时继续；可暂停、续讲、换题或停止。停止撤销未发计划，已开始的小段正常收尾。
- **只做动作**：不调用 TTS，不以静音或假台词占位。

真实抖音评论使用仓内 [DyHub](../../dyhub/README.md)，在工作台「来源设置」填写自己的授权直播间与本机采集器地址，再显式连接。采集默认使用独立浏览器资料，不读取日常 Chrome 个人资料。游戏侧的场次、投稿和投票说明见[评论与头像](../../romance-advisors/docs/05-抖音评论与头像.md)。停止订阅不会停止共享采集器。

候选评论先去重和过期，再由模型筛选，实际回答共用语音和动作发送器。礼物与欢迎使用可配置规则和统一轮次编排；待机小动作默认关闭，需自己选择有权使用的动作库并开启。昵称和评论只作为数据交给模型，没有工具权限。清唱未接入。

## 台词、动作与六档游戏外观

正常口播使用 A 编排：先生成台词与动作草案，再用同次 TTS 的真实词时间戳生成合法候选；多套候选时由文字模型选最终位置。每段最多 120 字、6 组局部动作，普通语音上限 30 秒。没有可行排程时拒绝发送，不删动作、不补静音、不自动付费重试。

GE 是眼神和表情，S 是短动作，Q 是收尾的眼神和表情。独立 GE 提前 1.1 秒，S 后 1.5 秒发 Q，Q 后至少 1 秒才发下一组；Q 不承担身体归位。发送器从实际成功写入重新计时，音频连续发送。这些时间是本机调度规则，无法证明云端动作恰好在某个词处发生。

游戏显示和动作锚点以 `text` 为准，可选 SSML 随冻结计划交给 Studio 统一解析。每轮口播后接低头发消息动作，实际 S 写出时公开聊天气泡。游戏开局、礼物跨档和退出游戏恢复口播档均复用同一云场与播放器。[六档配置及自动衔接边界](EXTERNAL_APPEARANCE.md)

Type16 形象切换没有成功 ack。游戏的 `applied` / `program_adopted` 只表示发送后保护与接收端健康检查通过、程序采用目标绑定继续调度，不表示视觉完成；失败或结果未知继续暂停。实际人物、声音、嘴形和动态换形应在自己的环境中观察。

## 自定义模型与可选 CloudBase

当前不是任意第三方 API 即插即用。正式文字传输位于 `bailian_ai.py`，百炼端点经过校验；`cloudbase_ai.py` 的 `StructuredBrain` 提供共用提示词和结构化计划校验。`automation.py` 创建默认 `BailianAI` 实例，并允许代码注入替代实例。开发自己的模型或云端 Agent 时，需实现筛选、回复、主持、提纲与最终动作选点等调用合同，以及状态、用量、错误和取消处理；保留来源验证、有限计划和唯一发送者保护。只改 URL 或模型名不能保证可用。

CloudBase 可完全不用。仓内 `CloudBaseAI` 与 `sdk/` 是独立适配入口，正常工作台不会因添加 `data/cloudbase.json` 自动切换。若选择它，请先在自己的账号创建环境、开通模型权限，再实现实例接线；配置需要自己的 `env_id`、`region`、`model` 与外部凭据文件引用。不要复用其他人的环境、密钥或托管 Agent。文字模型替换不会切换 TTS 或 Vidu。

## 文件与运行数据

| 入口 | 职责 |
| --- | --- |
| `server.py` | 本机接口、唯一播放器、会话与心跳保护 |
| `automation.py`、`comment_intake.py`、`director.py` | 评论候选、模型任务与主持主线 |
| `bailian_ai.py`、`cloudbase_ai.py` | 默认文字传输与共用结构校验 |
| `motion_component.py`、`component_live.py`、`live_session.py` | 动作、音频、串行发送与云端结束 |
| `timed_action_planner.py`、`action_schema.py` | 时间戳候选与动作字段校验 |
| `static/` | 控制台与播放器 |

`data/` 保存本机令牌、资产绑定和运行记录，不进入 Git。发送回执只能证明本机完成发送；RTC 帧、实际声音、录像及动作分别检查。控制台或播放器心跳失联、视频停滞、云场结束不明时会进入保护，修复后显式恢复，不自动重放失败内容。
